# T07-A 全局架构综合调研（基于局部实验）

## 1. 调研范围和前提

本报告基于工作区已有局部实验结果，重新评估智能阅读器的全局技术架构。

本轮明确排除**本地生成模型部署**：

- 不把本地生成模型作为一期可用问答路径；
- 不把当前设备的本地模型门禁结果解释为模型质量比较；
- 本地侧仍可承担文档解析、OCR、结构化、索引、检索、权限过滤和原文阅读；
- 问答生成只保留云端模型适配器和“无模型证据/原文降级”路径；
- 云端模型仅在授权允许时接收证据包，默认不接收未授权原文。

这不是最终技术选型，而是基于现有证据的架构候选收敛和下一轮验证边界。

## 2. 已阅读的七类局部实验结果

### 2.1 重要证据边界

- `TECH-QA-025-R01` 只证明官方 Codex CLI 链路可调用，不证明长期稳定性、成本或文档问答质量。
- `TECH-QA-017-R01`、`TECH-QA-019-R01` 等通用 API 结果受到账号/客户端策略或连接失败影响，不能作为云端模型质量结论。
- `TECH-MDOC-011-R07` 只发送项目自制合成证据，仍需 claim-level 人工复核，不能外推到真实文档。
- 所有局部实验都不支持“已有产品功能已经实现”的表述。

## 3. 基于局部结果的全局候选架构

### 3.1 候选 H：本地证据层 + 云端问答 + 无模型降级（当前主候选）

```text
文档导入
  -> 本地格式识别/解析/OCR
  -> CanonicalDocument
  -> 本地结构校验、分块、权限过滤
  -> 本地全文/向量/混合索引
  -> 证据契约检查
       |-- 证据完整且允许外部处理 -> 云端模型适配器
       |-- 敏感/未授权/证据不完整 -> 不调用模型
       |-- 云端不可用 -> 原文、检索结果或拒答
  -> 引用校验与人工复核策略
  -> 回答 + 页码/章节/bbox/原文
```

这里的“混合”不是本地模型和云端模型并存，而是**本地确定性文档处理与云端生成服务的组合**。本地模型生成能力不在一期范围内。

### 3.2 候选 C：云端端到端处理

文档直接发送云端解析/OCR/索引/问答服务。

当前不适合作为一期默认架构，原因是：

- 云端解析/OCR尚未完成同一批项目样本验证；
- 数据驻留、服务条款、费用和版本漂移尚未完成验证；
- 敏感文档默认不能外传；
- 当前局部结果显示解析和证据定位本身已经是主要风险，不能把风险整体转移给未验证的云端黑盒。

它仍可作为普通、明确授权文档的后续对照路径。

### 3.3 候选 L：纯本地证据/阅读路径，不含本地生成

本地完成解析、OCR、索引和检索；模型不可用时只提供：

- 原文阅读；
- 关键词/向量/混合检索结果；
- 页码、章节、bbox 和原文片段；
- 明确的“无法生成回答”状态。

它不是完整问答架构，但对敏感文档和离线场景是必要降级路径。

```text
  |

  |

  |

  |
  v

  |

Evidence Contract 完整性检查
  |

  |
  +--> 完整且允许外部处理：云端问答适配器
                              |

                    回答结构校验与引用校验
                              |
                              v
                    支持回答/人工复核/拒答
```

## 5. 由实验结果确定的模块边界

### 5.1 必须独立

1. **解析器适配器**：至少输出文本、物理页、bbox、块类型、版本和警告。
2. **OCR 适配器**：输出文本、行 bbox、置信度、页级状态和原页引用。
3. **结构校验器**：校验标题、脚注、表格、页眉页脚和阅读顺序，不直接静默修正原文。
4. **索引器**：全文索引和向量索引可分别替换；权限过滤先于排序和融合。
5. **检索器**：输出统一 `Evidence`，不能只返回字符串。
6. **Evidence Contract 检查器**：阻止缺少版本、源哈希、字符偏移或定位信息的证据进入引用问答。
7. **云端问答适配器**：只接收允许外发的证据包，记录服务/模型/协议版本和错误。
8. **引用校验器**：独立于问答模型，检查引用是否来自本次证据和正确文档版本。
9. **路由和降级控制器**：决定是否调用云端模型，处理网络、限流、权限和低置信度失败。

### 5.2 可以合并部署但不能合并契约

- 本地解析、OCR 和结构校验可以先部署为一个文档处理进程；
- 全文索引、向量索引和权限过滤可以使用同一存储服务；
- 云端问答适配器和回答格式化可以放在同一个服务；
- 原文阅读与证据展示可以共用界面。

合并部署不应删除适配器接口，否则后续无法比较 PyMuPDF/Docling/Tika，也无法独立替换云端模型。

### 6.2 Evidence Contract 的准入条件

证据进入云端问答前至少满足：

- `document_id`、`document_version`、`source_hash` 均存在；
- `block_id` 稳定且可回到 IR；
- 文本、页码或段落定位至少有一项可核验；
- 权限过滤已完成并记录策略版本；
- OCR/结构低置信度状态已被携带；
- 表格/公式/冲突内容有风险标记；
- 证据来源未被撤权、删除或标记为 stale。

当前结果中，页码、bbox 边界和路由检查已有证据，但版本、源哈希、字符偏移和完整支持链路仍未达标。

## 7. 全局架构实验结论

### 7.1 原始事实

1. 文本型 PDF 的字符可提取并不代表段落、标题、脚注和表格结构正确。
2. OCR 清晰样本可出现较好的页召回，但退化页和公开图片的精确问题通过率明显下降。
3. 真实中文 embedding 和混合检索在小样本上取得 Recall@3=1.0，但无答案误召回仍为 1.0。
4. 多文档合成 fixture 中权限、版本、删除和并发隔离通过，但真实生产索引和云端删除未验证。
5. 证据门控可以稳定拒绝无依据问题和进入人工复核的冲突问题。
6. 云端模型官方客户端链路可以运行，但完整问题集状态准确率、引用支持率和延迟仍不足以形成无监督问答承诺。
7. 本地生成模型环境未达到可安全开始质量实验的条件，本轮不考虑其部署。

### 7.2 项目组解释

当前主要风险不在“能否把模型接上”，而在于：

- 解析/OCR 产物是否可靠；
- 证据是否完整可追溯；
- 权限和版本是否在检索前生效；
- 低置信度和冲突是否阻止自动生成；
- 云端服务失败时是否仍可用。

因此架构中心应从“模型选择”转移到“本地证据层 + 云端受控生成 + 无模型降级”。

### 7.3 当前技术/需求结论

在不考虑本地生成模型的前提下，当前最有证据支持的候选是：

> **本地文档处理、OCR、结构化、权限过滤、索引和检索；在证据契约完整且文档允许外发时，调用云端问答；否则提供证据/原文/人工复核/拒答降级。**

这只是“受限可行的架构候选”，不是最终云端供应商或模型选型。

## 8. 一期范围建议

### 可以作为一期核心能力

- 文本型 PDF、Markdown、TXT 和 DOCX 的本地导入与结构化基线；
- 本地全文检索和经过门控的向量/混合检索；
- 文档、版本、权限和来源元数据保存；
- 物理页码、章节、bbox 和原文片段展示；
- 普通且明确授权文档的云端问答候选路径；
- 敏感/未授权/离线文档的原文与检索降级；
- 无依据问题拒答和冲突人工复核。

### 应列为有限支持或实验能力

- 扫描 PDF：仅清晰正向单栏的最佳努力支持；低置信度必须回看原页；
- 双栏 PDF：结构候选需人工/规则校验；
- 表格和公式：保留截图、bbox 和线性化文本，不承诺精确单元格问答；
- 多文档问答：先实现权限过滤、版本和冲突状态，再扩大自动回答范围；
- 云端问答：只对合成/授权数据验证，需人工 claim-level 复核。

### 当前不纳入一期承诺

- 本地生成模型部署；
- 复杂扫描件的自动精确问答；
- 无人工复核的跨文档冲突结论；
- 云端端到端解析/索引作为默认路径；
- 生产级物理删除、备份删除和供应商数据删除证明。

## 9. 下一轮全局实验设计

下一轮不再重复模拟 L/C/H 三路模型选择，而是验证“云端生成 + 本地证据层”的集成约束。

### `TECH-ARCH-003-R01`：证据契约到云端问答的集成门控

固定使用已有解析、OCR、检索和多文档结果，构造四类证据包：

1. 完整版本、源哈希、页码、bbox、字符偏移；
2. 缺少版本/源哈希；
3. OCR 低置信度或表格结构不可信；
4. 冲突、撤权或 stale 版本。

预期：只有第一类且授权允许外发的证据包进入云端适配器；其余进入检索展示、人工复核或拒答。

### `TECH-ARCH-003-R02`：云端不可用降级

模拟：连接失败、HTTP 403、超时、限流、非法 JSON、引用不在证据中。

预期：保留本地原文、检索和证据定位；不生成无依据答案；错误需进入实验记录。

### `TECH-ARCH-003-R03`：解析器替换回归

对同一文本型 PDF 使用 PyMuPDF、Docling 和 Tika 的适配输出，比较：

- IR 字段覆盖率；
- Evidence Contract 完整率；
- 页码/bbox/章节定位；
- 结构风险是否被正确传递；
- 是否需要重新解析、重新索引。

### `TECH-ARCH-003-R04`：权限和版本回归

使用已有多文档 fixture 和引用结果，验证撤权、删除、版本 stale 后，云端证据包不会包含旧证据或不可见文档。

## 10. 尚未解决的问题

1. 云端问答的长期服务稳定性、价格和数据保留政策仍未完成正式核对。
2. `TECH-RET-007-R01` 的证据契约字段缺失必须先修复，才能进行可信的云端引用实验。
3. 现有云端模型结果主要来自合成证据，真实授权文档上的质量尚未验证。
4. 证据包应发送原文片段、规范化文本还是脱敏文本，仍需数据合规决策。
5. OCR 低置信度阈值需要在至少 5 份真实授权扫描 PDF 上重新标定。
6. 文档解析器组合的标题、脚注、表格冲突优先级尚未固定。
7. 本地 embedding 是否纳入一期仍需结合设备资源、索引规模和数据策略单独决定；它不等同于本地生成模型部署。

## 11. 结论口径

> **原始事实**：局部实验已证明本地解析/检索/权限/证据门控链路具备可观察性；云端模型可通过官方客户端链路运行，但质量、引用和延迟指标仍有限；本地生成模型环境未准备好。  
> **项目组解释**：当前最稳妥的全局边界是把本地侧作为证据和治理层，把云端侧作为受控生成层，并把无模型阅读/检索作为正式降级路径。  
> **技术/需求结论**：一期暂不考虑本地生成模型；优先验证“本地证据层 + 云端问答适配器 + Evidence Contract + 无模型降级”的架构。  
> **尚未解决**：云端正式服务条款、真实授权文档问答、证据字段补齐和解析器替换回归仍需实验。

## 12. TECH-ARCH-004-R01：官方 CLI 云端适配器实验结果

本轮将云端调用实现为 Java 可替换适配器，调用路径严格复用问答实验中已验证的官方 Codex CLI：`codex exec --ephemeral --sandbox read-only --skip-git-repo-check --ignore-rules --json`。适配器通过 stdin 发送单条项目自制合成 Evidence Contract，未读取或上传真实项目文档，也未直接调用 OpenAI/Bearer API。

### 12.1 实验记录

结果文件：`experiments/minimal-chain-java/results/TECH-ARCH-004-R01.md`。

| 用例 | 门控/调用 | 实际结果 | 解释边界 |
|---|---|---|---|
| 完整、授权、高置信度 | `ALLOW_CLOUD`，调用 CLI | CLI 成功，JSON 合法，`status=answered`，本次耗时约 7.1 秒 | 仅证明本次客户端路径和合成提示可达，不证明模型质量 |
| 缺少 `source_hash` | `LOCAL_EVIDENCE_ONLY`，不调用 | 退回本地证据 | 说明证据契约字段是云端准入条件 |
| 禁止外部处理 | `LOCAL_EVIDENCE_ONLY`，不调用 | 退回本地证据 | 不把权限交给模型判断 |
| OCR 低置信度/结构风险 | `HUMAN_REVIEW`，不调用 | 转人工复核 | 低置信度内容不自动生成精确回答 |
| stale 文档 | `REFUSE`，不调用 | 拒答 | 防止旧版本进入回答 |
| CLI 不可用 | `ALLOW_CLOUD`，调用失败 | 回退本地证据和原文阅读 | 失败是正式路由状态，不是伪造本地答案 |

### 12.2 原始事实、项目组解释与技术/需求结论

- **原始事实**：门控拒绝的 4 类用例调用次数为 0；完整合成证据用例在一次运行中通过官方 CLI 返回合法 JSON；替换为不存在的 CLI 路径时适配器返回失败并完成本地回退。
- **项目组解释**：云端服务必须位于 Evidence Contract、权限/版本过滤和引用校验之后，且必须可被替换或禁用；CLI 可启动不等同于质量、成本、SLA、数据保留或合规保证。
- **技术/需求结论**：一期可以继续验证“本地证据层 + 受控云端问答 + 无模型降级”；门控拒绝、超时、非法 JSON、CLI 错误和引用不一致应作为可观测业务状态纳入接口，而不是只记日志。

### 12.3 对后续局部调研的约束

1. PDF 解析、OCR、结构识别和检索实验必须补齐 `document_version`、`source_hash`、稳定 `block_id`、页码/bbox 或字符范围，否则不能进入云端实验。
2. 云端问答局部实验继续使用同一官方 CLI 适配器，不再另造直接 API 路径；模型质量、成本和供应商比较另行设计，不从本轮可达性外推。
3. 引用实验必须在模型返回后独立检查 citation ID 是否属于本次授权证据，模型返回 `answered` 不自动放行。
4. 失败和离线路径必须保留原文、检索证据和定位信息，不能把云端不可用解释为整个阅读器不可用。

本轮仍不考虑本地生成模型部署，也没有形成最终云端模型或供应商选型结论。
