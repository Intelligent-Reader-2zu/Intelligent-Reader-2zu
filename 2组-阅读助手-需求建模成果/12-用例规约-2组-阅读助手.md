## 0. 阅读说明

1 组基线中，用例只以两种形式存在：V0.2 §5 的**一张清单表**（12 行，列出参与者/前置/结果/异常），和 SRS §4 的 **5 条一句话简述**（UC01/UC02/UC05/UC06/UC07/UC08/UC09+10）。两者都不是可执行的用例规约——没有编号化的主成功路径，也没有把异常路径落到冻结的状态名上。

本文件补这一块：**12 条用例全部按 UC01 的格式标杆完整填写**（编号化主成功路径 + 异常与降级路径表 + 后置条件 + 关联），字段内容取自 V0.2 §5 / SRS / SPEC，不新增语义。原 V0.3 初稿中 UC02/UC03/UC04/UC07/UC11/UC12 的 6 处 `【待补】` 主成功路径已于 2026-10-20 全部补齐。

**编号与状态名一律取自《编号规则与术语表》**，不得自造。

## 2. UC01 导入文档（完整样例）

| 项 | 内容 |
|---|---|
| 用例编号 | `UC01` |
| 用例名称 | 导入文档 |
| 主要参与者 | Reader |
| 前置条件 | 用户已进入工作区；文档库可用 |
| 触发事件 | 用户在文档库中选择"导入"并明确选定文件 |

**主成功路径**

1. 用户明确选择一个或多个文件（系统不遍历目录、不自动读取工作区，BR11）。
2. 系统校验文件格式与访问权限。
3. 系统计算 `source_hash`，登记 `Document` 与 `DocumentVersion`；若同一 `source_hash` 已存在有效版本，则不重复创建（SPEC §3.2）。
4. 系统创建 `ParseRun`，文档状态置为 `registered` 后进入 `queued`。
5. 系统向用户返回 `document_id`、`version_id`、`parse_run_id`（SPEC §7 `/documents/import`）。
6. 系统生成导入完成通知（`Notification`）。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 1a | 格式不支持 | 明确提示不支持及原因，不读入其他文件 | 不创建版本 |
| 1b | 权限不足 | 提示权限原因，不读入其他文件 | 不创建版本 |
| 3a | 同一 `source_hash` 已存在有效版本 | 不重复创建，提示已存在并定位到既有版本 | 复用既有 `DocumentVersion` |
| 4a | 解析任务创建失败 | 记录错误码，提示可重试或删除任务 | `ParseRun.status = failed` |

**后置条件**：`Document`、`DocumentVersion`、`ParseRun` 存在且状态可查；源文件保持只读未修改。

**关联**

- 业务规则：BR11、BR14
- 功能需求：FR-01
- 非功能需求：NFR-05（溯源字段）、NFR-13（格式优先级与明确提示）
- 领域对象：Document、DocumentVersion、ParseRun、Notification
- 图：A5（时序图·导入-解析-索引）、A1（状态图·文档处理）、用例图 UC01

### UC02 处理并索引文档

| 项 | 内容 |
|---|---|
| 用例编号 | `UC02` |
| 用例名称 | 处理并索引文档 |
| 主要参与者 | Local Parser/OCR、Reader |
| 前置条件 | 文档已登记（`UC01` 完成） |
| 触发事件 | 解析任务被调度 |

**主成功路径**

1. 系统调度解析任务，文档状态由 `queued` 进入 `processing`。
2. Local Parser/OCR 解析文档并产出统一中间表示（IR）：`Page`（`physical_page`、`page_label`、`asset_ref`）与 `ContentBlock`（`text`、`section_path`、`char_start/end`、`bbox`、`confidence`）（SPEC §3.2）。
3. 解析器写回 `ParseRun`（`parser_version`、`config_hash`、`status`、`warnings`）；全部内容块置信度达标时，状态由 `processing` 进入 `parsed`。
4. 系统在 IR 之上创建 `IndexingRun` 与 `Index`，记录 `version_id`、`index_type`（全文 / 向量）与权限范围。
5. 索引构建成功，状态进入 `indexed`；系统生成处理完成通知（`Notification`）（BR15）。
6. 用户可随时查询处理状态、进度、警告与错误码（SPEC §7 `GET /documents/{id}/status`）。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 2a | 扫描件 OCR 低置信 | 保留原页/截图并标注风险，**不承诺精确结构化问答**（BR07） | `ocr_low_confidence` → `needs_review`（`ERR-201`） |
| 2b | 双栏 / 表格 / 公式结构不确定 | 同上 | `layout_uncertain` → `needs_review`（`ERR-202`） |
| 3a | 解析器异常或文件损坏 | 记录错误码与重试次数，提示可重试或删除任务 | `failed`（`ERR-203`） |
| 3b | 解析超时 | 同上 | `failed`（`ERR-205`） |
| 4a | 全文索引构建失败 | 保留已解析结果，提示"当前仅可原文阅读" | `parsed`（索引未完成，`Index.build_status = failed`）（`ERR-206`） |
| 4b | 向量索引引擎缺失或未启用 | 降级为全文检索，明确提示 | `indexed`（仅全文）（`ERR-207`） |
| 5a | 用户删除失败任务 | 任务标记删除，不再占用队列 | `deleted`（`ERR-208`） |

**后置条件**：生成 IR、结构候选与索引；处理状态、进度与警告可见（关闭浏览器后仍可查）。

**关联**

- 业务规则：BR07、BR15
- 功能需求：FR-02
- 非功能需求：NFR-05（溯源字段）、NFR-11（处理耗时须记录）
- 领域对象：ParseRun、Page、ContentBlock、IndexingRun、Index、Notification
- 图：A1（状态图·文档处理）、A5（时序图·导入-解析-索引）

### UC03 管理文档空间

| 项 | 内容 |
|---|---|
| 用例编号 | `UC03` |
| 用例名称 | 管理文档空间 |
| 主要参与者 | Reader / Workspace Owner |
| 前置条件 | 工作区可用 |
| 触发事件 | 用户创建空间、筛选、收藏、删除或查看文档状态 |

**主成功路径**

1. 用户进入文档库，选择一个工作区或 `DocumentSpace`（BR11：系统不自动遍历工作区）。
2. 用户执行空间操作之一：新建 / 重命名空间、按条件筛选、收藏、删除文档，或查看某文档的处理状态。
3. 系统校验 `PermissionGrant`（`subject` / `resource` / `action`）；校验通过后执行操作。
4. 系统更新 `DocumentSpace` 与 `Document` 的归属关系，并把文档状态回显到文档库（状态名取自术语表 §1.4）。
5. 若操作为删除或撤权，系统按 BR06 触发失效传播：`DocumentVersion.stale` 置位，关联 `Index` 与引用一并标记 `stale`。
6. 系统写入 `AuditEvent`，并在传播完成时生成 `Notification`。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 3a | 无匹配 `PermissionGrant` | 拒绝操作并提示原因，**不做任何归属变更** | 不变更（`ERR-102` 口径同源） |
| 5a | 删除传播未完成 | 相关内容标记失效，**不得继续作为有效引用** | `stale`（`ERR-305`） |
| 5b | 文档版本已失效或已被撤权 | 同上 | `stale`（`ERR-303`） |
| 6a | 查看的文档正在处理中 | 返回当前状态而非结果，不假装已完成 | 保持 `queued` / `processing` |

**后置条件**：文档空间成员与文档归属更新，且删除 / 撤权传播**可审计**。

**关联**

- 业务规则：BR06、BR11
- 功能需求：FR-01
- 非功能需求：—（基线未列）
- 领域对象：DocumentSpace、Document、DocumentVersion、PermissionGrant、Index、AuditEvent、Notification
- 图：A1（状态图·文档处理）

### UC04 阅读文档与目录

| 项 | 内容 |
|---|---|
| 用例编号 | `UC04` |
| 用例名称 | 阅读文档与目录 |
| 主要参与者 | Reader |
| 前置条件 | 文档可打开 |
| 触发事件 | 用户打开已导入文档 |

**主成功路径**

1. 用户从文档库打开一个文档，系统加载其**当前有效** `DocumentVersion` 与 IR。
2. 系统按 `Page` 渲染正文与页码（同时给出 `physical_page` 与 `page_label`），并按 `ContentBlock.section_path` 生成目录 / 章节树。
3. 用户按页、章节或目录跳转；系统记录阅读位置，供下次继续。
4. 用户可对正文或选中文本发起后续动作：检索（UC05）、提问（UC06）、记笔记（UC09）。
5. 离线时：已导入文档仍可打开、阅读，并可执行**已建立索引的基础检索**（BR13、NFR-09）；AI 相关入口显示明确降级状态而非无响应。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 2a | 页码标签不确定（视觉页码 ≠ 物理页） | 双字段并列展示；引用回退到 `section_path` + 字符偏移 | `layout_uncertain` |
| 2b | 结构候选待人工复核 | 保留原页/截图与风险标记，目录标为"待复核" | `needs_review` |
| 1a | 文档被撤权或删除 | 不打开正文，提示来源已失效 | `stale` / `deleted` |
| 5a | 离线且索引不可用 | 仅提供原文阅读，检索入口提示不可用 | 阅读可用（BR13） |

**后置条件**：用户按页 / 章节 / 目录 / 阅读位置浏览；**离线仍可用**（BR13）。

**关联**

- 业务规则：BR07、BR13
- 功能需求：FR-02（含 SRS-FR03 阅读与目录）
- 非功能需求：NFR-01（引用可回页/章节/原文）、NFR-11（打开与首屏耗时须记录）
- 领域对象：DocumentVersion、Page、ContentBlock、Index
- 图：A1（状态图·文档处理）

### UC05 检索文档或授权文档集

| 项 | 内容 |
|---|---|
| 用例编号 | `UC05` |
| 用例名称 | 检索文档或授权文档集 |
| 主要参与者 | Reader |
| 前置条件 | 文档已索引且用户有权访问 |
| 触发事件 | 用户提交检索词或模糊问题 |

**主成功路径**

1. 用户选择检索范围：当前文档，或显式选定的 `DocumentSet`（NFR-06：由用户选择，不由系统推定）。
2. 系统在检索排序之前先完成权限过滤（BR01）；缓存命中时同样先过滤（`ERR-307`）。
3. 系统执行全文 / 语义 / 混合检索（`Index.index_type`），返回候选 `ContentBlock` 与 `Evidence`。
4. 系统按来源文档分组返回结果，每组展示来源、版本、页码 / 章节与原文片段。
5. 用户可点选结果跳回原文（UC08 口径），或基于结果发起提问（UC06）。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 2a | 权限过滤后集合为空 | 返回"无答案"并提示调整范围，**不得用看似相关的结果伪装** | 降级为原文阅读（BR04、BR05）（`ERR-301`） |
| 3a | 结果噪声过高 / 无高置信命中 | 标注置信度，提示缩小范围或改写提问 | 正常返回但不承诺答案 |
| 4a | 来源版本已变化、索引未重建 | 该来源的结果标记失效 | `stale`（`ERR-304`） |
| 4b | 来源已撤权 | 同上 | `stale`（`ERR-303`） |
| 3b | 向量索引不可用 | 降级为全文检索并明确提示 | `indexed`（仅全文）（`ERR-207`） |

**后置条件**：结果展示来源文档、版本、页码 / 章节与原文片段；跨库问答（FR-11）不在本期范围。

**关联**

- 业务规则：BR01、BR04、BR05、BR08
- 功能需求：FR-03
- 非功能需求：NFR-02（权限过滤先于检索排序）、NFR-06（集合上限候选 20 份）
- 领域对象：Query、DocumentSet、Index、Evidence、PermissionGrant
- 图：A6（活动图·检索）

### UC06 对当前文档/选中文本提问

| 项 | 内容 |
|---|---|
| 用例编号 | `UC06` |
| 用例名称 | 对当前文档/选中文本提问 |
| 主要参与者 | Reader、Authorized Model Service |
| 前置条件 | 有可用证据且满足外发策略 |
| 触发事件 | 用户提交问题 |

**主成功路径**

1. 用户提交查询，系统创建 `Query`（单文档提问不构造 `DocumentSet`，见 R-04）。
2. 系统完成权限过滤与门控，组装 Evidence Contract（版本有效、敏感级别允许、置信度达阈值）（BR01、BR02）。
3. 系统按 BR12 逐文件展示拟外发范围、模型服务与用途，取得**本次**明确确认（`UploadConfirm`，`Policy.require_per_file_consent`）。
4. 系统调用云端模型；回答状态经 `requested → retrieving → evidence_checked → generating`。
5. 系统逐条校验 `Claim` 与 `Citation`：引用必须来自本次 allow-list（BR03），支持状态记入 `support_status`；状态进入 `citation_checked`。
6. 系统展示带引用的回答，状态进入 `answered`；用户可点击引用进入 UC08 核验。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 3a | 用户拒绝本次外发 / 策略禁止云端 | 不调用云端，仅返回本地证据与原文 | `local_evidence_only`（`ERR-401`、`ERR-306`） |
| 2a | 证据覆盖不足 | 标记待人工复核，提示补充检索范围 | `needs_human_review`（`ERR-509`） |
| 2b | 无依据问题 | 明确"无法确认"，**不得伪装成有依据回答** | `refused`（`ERR-510`） |
| 4a | 云端模型超时或失败 | 提示模型不可用，返回原文 / 检索结果 | `model_failed`（`ERR-501`、`ERR-502`） |
| 5a | 引用不在 allow-list / 页码越界 / `quote` 不匹配 / 定位失败 | 标记该引用失效，**禁止显示为已核验答案** | `citation_invalid`（`ERR-504`–`ERR-508`） |
| 5b | 回答所依据的证据过期或撤权 | 不复用旧答案，重新检索 | `stale`（`ERR-303`、`ERR-304`） |

**后置条件**：`Answer` 及其 `Claim` / `Citation` 存在；本次外发确认留有 `AuditEvent`。

**关联**

- 业务规则：BR01、BR02、BR03、BR04、BR05、BR12
- 功能需求：FR-04（含 SRS-FR06）
- 非功能需求：NFR-10（30 秒流式反馈为候选目标）
- 领域对象：Query、Answer、Claim、Citation、Evidence、ModelConfig、Policy、AuditEvent
- 图：A2（状态图·回答生成）、A3（时序图·问答与引用校验）、A4（时序图·逐文件外发确认）

### UC07 生成摘要/要点

| 项 | 内容 |
|---|---|
| 用例编号 | `UC07` |
| 用例名称 | 生成摘要/要点 |
| 主要参与者 | Reader、Authorized Model Service |
| 前置条件 | 文档或章节已选定 |
| 触发事件 | 用户请求全文或章节摘要 |

**主成功路径**

1. 用户选定范围：整篇文档或指定章节（对应 `DocumentVersion` 与 `section_path`）。
2. 系统检索该范围内的 `ContentBlock`，组装 Evidence Contract（版本有效、权限通过、置信度达标），生成 `Query`。
3. 系统按 BR12 逐文件展示外发范围、模型服务与用途，取得本次明确确认。
4. 系统调用 Authorized Model Service 生成全文提纲 / 章节要点；回答状态经 `requested → retrieving → evidence_checked → generating`。
5. 系统为每条关键结论绑定 `Citation`（SRS-FR05「关键结论绑定引用」），校验引用来自本次 allow-list（BR03）；状态进入 `citation_checked`。
6. 系统展示带引用的提纲与要点，状态进入 `answered`；用户可点击引用进入 UC08 核验。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 2a | 证据覆盖不足 | 标记待复核，提示补充范围 | `needs_human_review`（`ERR-509`） |
| 2b | 证据低置信或版本失效 | 仅返回原文 / 检索结果，不生成确定性结论 | 降级（原文 / 检索）（BR07、BR13） |
| 3a | 用户拒绝本次外发 | 不调用云端，仅提供本地证据与原文 | `local_evidence_only`（`ERR-401`） |
| 4a | 云端模型超时或失败 | 提示模型不可用，返回原文 / 检索结果 | `model_failed`（`ERR-501`、`ERR-502`） |
| 5a | 引用定位失败或不在 allow-list | 标记失效，禁止显示为已核验答案 | `citation_invalid`（`ERR-504`–`ERR-508`） |

**后置条件**：生成带引用的提纲与要点；摘要同样受证据契约与引用校验约束，不因"是摘要"而放宽。

**关联**

- 业务规则：BR02、BR03、BR04、BR12
- 功能需求：FR-05
- 非功能需求：NFR-10（长任务须显示进度）
- 领域对象：Query、Answer、Claim、Citation、Evidence、Policy、AuditEvent
- 图：A2（状态图·回答生成）、A3（时序图·问答与引用校验）

### UC08 核验回答引用

| 项 | 内容 |
|---|---|
| 用例编号 | `UC08` |
| 用例名称 | 核验回答引用 |
| 主要参与者 | Reader |
| 前置条件 | 回答包含 `Citation` |
| 触发事件 | 用户点击某条引用 |

**主成功路径**

1. 用户点击回答中的一条引用。
2. 系统按 `Citation.evidence_id` 定位来源 `Evidence` → `ContentBlock` → `Page` 与 `DocumentVersion`。
3. 系统跳转到对应页码 / 章节，并高亮原文片段或展示 `bbox`。
4. 系统回显该引用对应的 `support_status`（`supported` / `partial` / `conflicting` / `unsupported` / `locator_failed`）。
5. 用户可在原文位置直接发起记笔记（UC09）。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 2a | 来源版本已变化或已撤权 | 提示来源已变更，引用标记失效 | `stale`（`ERR-303`、`ERR-304`） |
| 3a | 引用定位失败 | 提示无法定位，**禁止显示为已核验答案** | `citation_invalid`（`ERR-508`），`support_status = locator_failed` |
| 3b | 引用 `quote` 与原文不匹配 | 同上 | `citation_invalid`（`ERR-507`） |
| 4a | 来源之间存在冲突 | 按 `support_status = conflicting` 显式标记，不以单条为准 | 保留冲突标记 |

**后置条件**：用户回到来源版本与原文位置；核验结果不修改回答内容本身。

**关联**

- 业务规则：BR03、BR06
- 功能需求：FR-06（含 SRS-FR07）
- 非功能需求：NFR-01（引用可回到版本、页码 / 章节与原文）
- 领域对象：Citation、Evidence、ContentBlock、Page、DocumentVersion
- 图：A3（时序图·问答与引用校验）
- 备注：挂载关系见 R-02（`UC08 ..> UC06` / `UC08 ..> UC07` 为 `<<extend>>`），裁决材料见《[R-02裁决材料](./R-02裁决材料.md)》

### UC10 导出阅读成果

| 项 | 内容 |
|---|---|
| 用例编号 | `UC10` |
| 用例名称 | 导出阅读成果 |
| 主要参与者 | Reader |
| 前置条件 | 已选择摘要、笔记或引用；用户已指定保存位置 |
| 触发事件 | 用户提交导出 |

**主成功路径**

1. 用户选择导出范围与格式（摘要 / 笔记 / 引用）。
2. 用户**指定目标路径**（BR11：只写用户指定位置）。
3. 系统创建 `ExportJob`，记录 `format`、`scope`、`target_path`、`status`、`created_at`（SPEC §6）。
4. 系统在写入前后对**源文件**执行差分检查，确认源文件未被修改（BR14）。
5. 系统写入导出文件并显示写入结果。
6. 若导出内容含引用，系统保留其来源版本与位置关联（BR09）。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 1a | 导出范围为空 | 提示"没有可导出的内容"，不创建任务 | 不创建（`ERR-603`） |
| 4a | 源文件差分检查不通过 | 中止导出，提示源文件被改动 | `ExportJob.status = failed`（`ERR-606`） |
| 2a | 目标路径不存在或无写权限 | 提示且**不写入** | 不写入（`ERR-604`） |
| 5a | 写入失败（IO） | 记录 `ExportJob.error`，提示可重试 | `ExportJob.status = failed`（`ERR-605`） |
| 6a | 导出内容中的部分引用已失效 | 在导出文件中标注失效引用，不静默剔除 | 正常导出 + 标注（`ERR-607`） |

**后置条件**：指定位置生成衍生文件；**源文件未被修改**；失败时留有 `error` 且不静默覆盖。

**关联**

- 业务规则：BR09、BR14
- 功能需求：FR-08（含 SRS-FR09）
- 非功能需求：NFR-05（保留溯源字段）
- 领域对象：ExportJob、Note、Citation、DocumentVersion
- 图：A7（活动图·笔记与导出）

### UC11 配置模型与隐私边界

| 项 | 内容 |
|---|---|
| 用例编号 | `UC11` |
| 用例名称 | 配置模型与隐私边界 |
| 主要参与者 | Workspace Owner |
| 前置条件 | 用户进入设置页 |
| 触发事件 | 用户修改模型或隐私设置 |

**主成功路径**

1. Workspace Owner 进入 `settings` 页面，系统展示当前 `Policy` 与 `ModelConfig` 取值。
2. 用户设置回答策略：`Policy.require_citation`（是否强制引用）、无依据时是否显示"无法确认"。
3. 用户设置外发策略：`Policy.require_per_file_consent`（逐文件外发确认）、`Policy.confidence_threshold`、拟用模型服务与用途（`ModelConfig.provider` / `model_name` / `routing_policy`）（SPEC §4.2）。
4. 用户设置本地文件访问范围与 `ModelConfig.allow_cloud`（BR11：默认只访问明确选择的范围）。
5. 系统校验配置一致性；通过后保存 `Policy` 与 `ModelConfig`。
6. 系统写入 `AuditEvent`，并把设置回显到 `settings` 与 `answer-more` 页面（A9）。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 5a | 配置冲突（如 `require_citation = false` 与 BR04 冲突） | 拒绝保存并提示冲突原因 | 不落库 |
| 5b | 策略拒绝（越权修改） | 拒绝并提示 | 不落库 |
| 5c | 尝试关闭逐文件外发确认 | **拒绝**：该策略不允许关闭（BR12、NFR-08） | 不落库（`ERR-404`） |
| 5d | `allow_cloud = false` 时用户仍发起云端问答 | 按策略走本地证据路径 | `local_evidence_only`（`ERR-306`） |

**后置条件**：设置覆盖"回答需引用、无依据显示无法确认、外传确认、本地文件访问范围"；**逐文件外发确认不得被默认关闭**。

**关联**

- 业务规则：BR02、BR10、BR11、BR12
- 功能需求：FR-09（含 SRS-FR10）
- 非功能需求：NFR-08（外发确认）、NFR-14（数据与合规可追溯性）
- 领域对象：Policy、ModelConfig、PermissionGrant、AuditEvent
- 图：A4（时序图·逐文件外发确认）、领域模型、A9（界面导航图）

### UC12 查看处理/核验通知

| 项 | 内容 |
|---|---|
| 用例编号 | `UC12` |
| 用例名称 | 查看处理/核验通知 |
| 主要参与者 | Reader |
| 前置条件 | 系统产生事件 |
| 触发事件 | 解析完成、低置信、摘要完成、引用失效或待复核状态产生 |

**主成功路径**

1. 系统事件产生时创建 `Notification`，字段为 `type`、`resource_ref`、`created_at`、`read`（初始 `false`）。
2. 通知类型覆盖：解析完成、低置信 / 结构不确定（`needs_review`）、摘要完成、引用失效（`stale`）、引用定位失败（`citation_invalid`）、待人工复核（`needs_human_review`）。
3. 用户打开 `notifications` 页面，系统按类型与时间列出未读通知。
4. 用户点击通知，系统按 `resource_ref` 跳转到对应对象（`ParseRun` / `Answer` / `Citation` / `DocumentVersion`），并展示**可解释状态与错误码**。
5. 用户标记已读，`Notification.read` 置位。

**异常与降级路径**

| 编号 | 触发条件 | 系统响应 | 结果状态 |
|---|---|---|---|
| 1a | 同一事件重复产生通知 | 按（`type` + `resource_ref`）去重，不重复投递 | 单条通知 |
| 3a | 事件延迟到达 | 按 `created_at` 排序并标注延迟，不隐藏 | 通知照常可见 |
| 4a | 通知指向的对象已失效 | 展示失效原因与错误码，**不跳转到空对象** | 提示失效（`ERR-303` 等） |

**后置条件**：用户可查看并标记已读；`Notification` 可改，而 `AuditEvent` **只增不改**（术语表 §2.2）。

**关联**

- 业务规则：BR04、BR15
- 功能需求：FR-10（含 SRS-FR11）
- 非功能需求：—（基线未列）
- 领域对象：Notification、AuditEvent、ParseRun、Answer、Citation
- 图：A5（时序图·导入-解析-索引）、领域模型
