## 1. 背景与本轮目标

1 组已完成需求调研，并额外交付了一套需求建模基线（需求模型 V0.2、SRS V1.0、SPEC V1.0、三张图）。

2 组本轮工作**不是从零建模**，而是在 1 组基线上做 **V0.3 增量**，目标有三：

1. **修订**：改正基线中的编号错位、图关系错误、领域模型多重度与缺类问题；
2. **补全**：补齐 1 组漏交的用例规约、追踪矩阵、TBD 验证方案；
3. **新增**：做出 1 组完全没有的部分（状态图、时序图、界面模型、用户访谈证据）。

> 课程要求两组在技术路线/迭代过程上有区分度。**2 组的区分度就建立在第 3 类"新增"上**，这也是本次评分的核心增量。
> **因此第 3 类不由单一组员独占——骨架由组长亲自起草，组员只在骨架上做增量。**

## 3. 协作规则（硬约束，违反需返工）

### 3.1 目录与命名
- 根目录：`docs/需求建模/2组-work/`
- 子目录：`图形/`（廖欣豪）、`文档/`（朱紫轩）、`界面/`（程禹轩）、`访谈/`（汪昊）
- 命名规范：文档用 `V0.3-<主题>.md`；图用 `<图类型>-<主题>.puml`（图类型取 状态图/时序图/活动图/用例图/领域模型）。
- **本地 PlantUML 插件的渲染产物（`out/` 目录）不入库**，最终出图以 CodeArts 平台为准。

### 3.2 基线规则
- 一切以仓库现有 **V0.2 基线**为准，**不得自造**概念、状态名、编号。
- 新增内容必须标注来源，写法：`（承接 V0.2 §用例清单 UC05）` 或 `（来源：SPEC §5.2）`。
- 确需偏离基线时，先在工作群提出，由组长确认后统一修改，**不允许各自改一套**。

### 3.3 工具约束
- 课程强制：建模图须使用**华为 CodeArts Modeling** 正式建档出图。
- 执行流程：先出 PlantUML 草图定结构 → 在 CodeArts 中正式建档出图 → 导出 PNG/SVG 入库。
- **CodeArts 项目由组长统一创建**，成员加入同一项目，图与需求条目建立追踪。
- ⚠️ **待验证项**：CodeArts 是否支持导入外部 `.puml`。组长先试跑 1 张图确认落地方案（导入 vs 手工重建）后再通知全员，**不必等这个结论才开始写内容**。

### 3.4 提交约束（重要）
- 本仓库为 **Public 公开仓库**。
- **以下内容一律不得 push**：访谈录音、访谈记录原件、姓名/学号/联系方式、`部分样本.zip`、`伪前端.zip` 等含个人或受限信息的文件。
- 允许 push 的：`.md` / `.puml` / `.png` / `.docx` 等不含个人信息的成果。
- 原始访谈记录请放在 `访谈/raw-local/`（该目录约定不入库，已在 `.gitignore` 中排除）。

### 3.5 术语与编号
- 统一口径见 [`编号规则与术语表.md`](./编号规则与术语表.md)（**V1.0 冻结版，2026-10-18**），全员必须按此执行。
- 三条要点：**不自造**编号/状态名/类名；**`FR` 与 `NFR` 编号带连字符**（`FR-01`、`NFR-01`）；引用必标来源。
- 编号空间：`UC01–UC12`、`BR01–BR15`、`FR-01–FR-12`、`NFR-01–NFR-13`、`SURVEY-001-Q1~SURVEY-011-Q11`、`INT-001` 起（仅此可新增）、`TBD-1~TBD-12`。

### 3.6 Git 提交规范
- 分支策略、提交信息格式、PR 流程、禁止事项**另见** [`2组Git协作规范.md`](./2组Git协作规范.md)。
- 两条底线：**不许直接 push 到 `main`**；**`git add` 必须按文件名加，不许 `git add .`**。
- 2 组仓库已就绪（`main` 已开分支保护，组员 Write 权限已配置），**推送通道无阻塞，可正常提交**。
