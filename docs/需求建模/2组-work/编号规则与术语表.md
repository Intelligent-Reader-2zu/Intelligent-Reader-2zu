### 1.4 状态与枚举（冻结，不得自造）

**文档处理状态**（出处：V0.2 §8、SPEC §3.1）

- 正常流转（5）：`registered` → `queued` → `processing` → `parsed` → `indexed`
- 异常分支（6）：`needs_review`、`ocr_low_confidence`、`layout_uncertain`、`failed`、`stale`、`deleted`

**回答状态**（出处：V0.2 §8、SPEC §5.1 §5.2）

- 正常流转（6）：`requested` → `retrieving` → `evidence_checked` → `generating` → `citation_checked` → `answered`
- 分支状态（6）：`local_evidence_only`、`needs_human_review`、`refused`、`model_failed`、`citation_invalid`、`stale`

> ⚠️ 注：V0.2 §8 的分支状态只列了 5 个，**漏了 `stale`**（SPEC §5.2 降级规则表中有）。本表按 6 个冻结，依据 SPEC §5.2。

**Claim 支持状态 `support_status`**（出处：V0.2 BR04、SPEC §5.1）

`supported`（已支持）、`partial`（部分支持）、`conflicting`（冲突）、`unsupported`（未支持）、`locator_failed`（定位失效）

### 2.2 易混术语辨析（必须区分）

| 易混对 | 区别 |
|---|---|
| **Evidence 证据** vs **Citation 引用** | 证据是原文片段本身；引用是回答里指向某条证据的落点（含 quote、页码、locator）。一条证据可被多条引用使用 |
| **Claim 断言** vs **Answer 回答** | 回答是整体产出（含状态、模型、不确定度）；断言是回答内部可独立核验的句子，每条断言绑定 0..n 条引用 |
| **Policy 策略** vs **PermissionGrant 权限授权** | 权限授权回答"谁能访问哪个资源"（subject/resource/action）；策略回答"系统在什么条件下允许外发与生成回答"（是否强制引用、是否逐文件确认、置信度阈值）。修改入口与生命周期不同 |
| **Notification 通知** vs **AuditEvent 审计事件** | 通知面向用户、可标记已读（UC12）；审计事件是只增不改的留痕（BR12 的逐文件确认记录），不可删改 |
| **ParseRun 解析运行** vs **IndexingRun 索引运行** | 前者产出页面与内容块（IR），后者在 IR 之上建全文/向量索引；两者可分别失败与重试 |
| **Document 文档** vs **DocumentVersion 文档版本** | 文档是逻辑实体；版本是一次导入的内容快照（source_hash 唯一），引用与笔记必须绑定版本而非文档 |

## 3. 使用规则

1. **不自造**。编号、状态名、类名、术语一律取自本表；表中没有的，先问组长，不要自己拼一个"看起来对"的。
2. **引用必标来源**。写作时用 `（承接 V0.2 §用例清单 UC05）`、`（来源：SPEC §5.2）`、`（依据：BR12）` 三种写法之一。
3. **发现冲突先记录、不擅自改**。基线与本表、或基线与基线之间矛盾时，登记到本表 §4 与《[V0.3-需求追踪矩阵](./文档/V0.3-需求追踪矩阵.md)》§6，由组长统一裁决。
4. **新增编号只在指定空间内顺延**。可在既有段内新增的只有 `INT-`（汪昊）与 `ERR-`（§1.6，段位不可扩展）；`NFR-14` 为 2 组新增项（§1.3）。其余前缀已满号，不得新增。
5. **本表变更须同步**。组长更新本表后，须在组内通知，并同步 `V0.3-需求模型.md` 与图形文件中的引用。
