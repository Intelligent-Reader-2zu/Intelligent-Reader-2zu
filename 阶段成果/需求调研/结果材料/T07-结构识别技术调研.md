# T07 结构识别技术环节调研

> 项目：智能笔记助手——内置 AI 助手的智能阅读器  
> 技术环节：第三个环节——结构识别  
> 日期：2026-09-29  
> 文档性质：调研与最小实验设计，不构成最终解析器选型

## 0. 结论先行

结构识别不是“把文件转成一段文字”，而是建立一个可回溯的文档结构图：标题和层级、章节、段落、列表、表格、脚注、图片/图注、代码块、公式、引用编号，以及它们的父子和引用关系。建议本项目采用两层结果：

1. **规范 JSON IR 作为唯一事实来源**：保留元素类型、层级、顺序、页/行/DOM 定位、bbox、原文偏移、置信度和资产引用。
2. **按场景派生 Markdown/纯文本**：用于预览、全文索引和模型输入；派生结果不能覆盖 JSON，也不能丢掉表格、公式、脚注和坐标信息。

已有 `TECH-DOC-007-R02` 说明“字符完整”与“结构正确”是两个问题：三种解析器在三份自制文本 PDF 上归一化字符召回均为 1.0，但 PyMuPDF 双栏样本严格段落边界召回仅 0.2857；Docling 标题 F1 为 0.8、0.9091、0.8，脚注召回均为 0，双栏样本表格单元格文本准确率为 0.7778；Tika 没有元素级页码、bbox、标题、脚注和表格网格。这些结果支持“低层坐标证据 + 结构解析 + 原始输出保留”的组合，而不支持只用纯文本或单一工具。

## 1. 结构识别的对象和边界

### 1.1 统一对象模型

把文档看成带顺序的树/图，而不是字符串：

```text
Document
  Section(level=1)
    Section(level=2)
      Paragraph
      List -> ListItem -> Paragraph
      Table -> Row -> Cell
      Figure -> Caption
      Equation
      CodeBlock
      Footnote
  Reference / CitationLink
```

树表示章节父子关系，图边表示“正文中的 [3] 指向参考文献 [3]”“脚注标记指向脚注正文”“图注属于图片”等关系。解析器输出的阅读顺序是独立字段，不能仅由树的深度优先遍历推定。

### 1.2 各格式的标题层级来源

| 来源 | 可靠信号 | 常见不确定性 | 建议策略 |
|---|---|---|---|
| PDF | 书签/outline、目录链接、编号模式（`1`/`1.1`）、字体和位置、跨页重复模式 | 书签缺失；目录只是普通文本；字体大小不等于语义；双栏排序错误 | 书签/显式编号优先；版面特征只作为预测证据；保存 `heading_source` 和置信度，无法判定时保留 `unknown` |
| Word/DOCX | `Heading 1..9` 样式、OOXML 大纲级别、标题编号、目录字段 | 手工加粗不一定是标题；样式被覆盖；最终分页由渲染器决定；脚注/文本框在不同库中支持不一致 | 样式和 outline level 作为主信号，编号作为校验；记录样式名和原始段落索引；视觉页码单独渲染验证 |
| Markdown | ATX `#`、Setext 标题、AST 节点层级 | CommonMark/GFM/扩展语法差异；跳级（H2 后 H4）；HTML 混入 Markdown | 固定方言和插件；保留原始行号；不自动把 H2→H4 重写成连续层级 |
| 网页 HTML | DOM 的 `h1..h6`、`aria-level`、`<article>/<section>`、目录链接、`id`/锚点 | SPA 动态渲染、导航/广告/侧栏、重复移动端 DOM、shadow DOM/iframe、无语义 `<div>` | 保存渲染后 DOM；结合 Readability/Trafilatura 清理正文；保留 URL、CSS selector/XPath、锚点和抓取时间 |

标题识别结果应同时保存 `level`（文档层级）、`label`（如“2.1”）、`title`、`parent_id`、`heading_path`、`source_signal` 和 `confidence`。不要把视觉字号直接当成标题级别。

## 2. 版面因素及处理

### 2.1 双栏、跨页、页眉页脚、脚注

- **双栏**：先检测栏区域，再在栏内按 y/x 排序；跨栏标题、跨栏图片和参考文献标题需要作为全页元素处理。不能把 `sort=True` 或字符坐标简单排序当作自然阅读顺序。失败时保留“左栏/右栏”区域和页面级文本，禁止静默拼成自然段。
- **跨页段落**：相邻页末/页首若字体、缩进和行距一致，可合并为一个逻辑段落，但必须保留两个物理范围（`spans`）；标题、脚注和表格页首/页尾不能按普通段落合并。
- **页眉页脚**：通过重复文本、固定 y 区域、字体/分隔线和页面位置识别。保留为 `header`/`footer` 元素并在检索中降权，而不是从原始结果删除，否则无法复核页码和引用。
- **脚注/尾注**：脚注标记、脚注正文、页码和 bbox 要分开存储，并用 `footnote_of`/`marker_for` 关联。脚注不应插入正文阅读顺序；若无法识别，至少保留区域和原文。
- **打印页码**：分开记录 `physical_page`（0/1-based 明确约定）与 `printed_page_label`（例如 `iii`、`3`）。DOCX 若没有稳定渲染页码，使用段落索引、标题路径和字符偏移作为引用替代。

### 2.2 表格、公式、图片说明和引用编号

| 对象 | 结构化表示 | 重要校验 |
|---|---|---|
| 表格 | `table` + `row` + `cell`；cell 保存 `row_index`、`col_index`、`rowspan`、`colspan`、文字、bbox；跨页表格用 `table_group_id` | 行列数、合并单元格、单元格文本位置、跨页连续性；无法恢复时输出表格截图 + 线性化文本 |
| 公式 | `equation`，保存 LaTeX/MathML（若可信）、原始文字、图片/bbox、编号（如 `(1)`） | 公式区域召回、符号/上下标错误率；不把普通 OCR 文本冒充精确公式 |
| 图片/图注 | `figure` 与 `caption` 分开，`caption_of` 建边；保存原图或裁剪资产引用、bbox、页码、alt text | 图片和图注是否配对；图片内文字不要默认等于正文 |
| 代码块 | `code_block`，保存语言提示、原文换行、缩进和行号范围 | 等宽区域、围栏/样式边界、缩进不能被段落归一化破坏 |
| 引用编号 | 正文中的 `[3]`/`(Smith, 2024)` 作为 `citation_marker`，参考文献作为 `bibliography_entry`，用 `refers_to` 关联 | 编号归一化不能改写原文；无法解析目标时保留 marker 和文本位置 |

表格和公式即使无法理解语义，也必须被识别为非普通段落的对象。这样问答可以知道“证据来自表格/公式”，界面可以跳转原图，检索也不会把单元格顺序错误地当成自然语言。

## 3. 普通文本提取、版面分析与结构化输出比较

| 方案 | 能得到什么 | 优点 | 主要缺陷 | 本项目定位 |
|---|---|---|---|---|
| 纯文本提取 | 字符串、换行、少量页分隔 | 快、便宜、易索引；Tika 可作为 Java 基线 | 丢失 bbox、层级、表格网格、脚注关系和资产；双栏顺序不可见 | 兜底和全文检索输入，不作为唯一事实 |
| 版面分析 | 页面区域、栏、标题/正文/表格/图片等类别和坐标 | 能解释双栏、表格、图注和引用定位；适合 PDF/扫描页面 | 需要模型或规则；阅读顺序、细粒度语义和跨页关系仍可能错误 | PDF 主路径的低层证据和结构候选 |
| 结构化 JSON | 元素树/图、属性、关系、来源和置信度 | 可验证、可增量修复、支持导航/检索/问答/引用 | 设计复杂；版本兼容和字段完整性需要治理 | **规范 IR，推荐** |
| Markdown 输出 | 标题、段落、列表、表格、代码等线性表达 | 人可读、适合预览和模型上下文；Docling/Azure 等可直接导出 | 通常丢页码/bbox、置信度、脚注边界、合并单元格和资产关系；不同方言不一致 | 从 JSON 派生的展示/索引格式 |

推荐双输出：`canonical.json`（完整、可追溯）+ `derived.md`（可读、可检索）+ `plain.txt`（兼容性兜底）。任何派生输出都记录 `derived_from` 和生成器版本。

## 4. 建议的结构识别结果字段

### 4.1 文档级

```text
doc_id, source_uri, source_hash, source_format, mime_type
parser_name, parser_version, model_version, config_hash
language, page_count, created_at, processing_status
structure_confidence, warnings[], raw_output_ref
```

### 4.2 元素级

```text
element_id, element_type, text, normalized_text
ordinal, parent_element_id, children_ids[], heading_path
heading_level, label, role, reading_order_index
physical_page, printed_page_label, page_span[]
bbox {x, y, width, height, coordinate_system}
char_start, char_end, source_line_start, source_line_end
column_id, confidence, confidence_by_field{}
asset_ref, alt_text, language, style_ref
```

`role` 用于 `body/header/footer/footnote/caption/reference` 等家具或语义角色；`element_type` 用于 `heading/paragraph/list/table/cell/figure/equation/code_block` 等结构类型。二者不要混成一个枚举。

### 4.3 关系和表格专用字段

```text
relation_id, relation_type, source_element_id, target_element_id
table_id, row_index, col_index, rowspan, colspan, table_group_id
citation_key, citation_marker, footnote_key, caption_of
```

现有 `DocumentBlock(blockId, type, text, lineStart, lineEnd, headingPath)` 可作为最小兼容视图，但不足以支撑 PDF 引用。建议先在解析实验适配层使用上述 IR，确认字段稳定后再扩展 `CanonicalDocument`，避免把某一解析器的字段直接固化为生产模型。

## 6. 适合本项目的样本类型

首轮建议 6 类、每类至少 2 份（1 份自制可控样本 + 1 份有明确许可的真实材料），并登记 SHA-256、许可、语言和风险：

1. 单栏文本 PDF：目录、编号标题、页眉页脚、脚注、打印页码。
2. 双栏论文/技术报告 PDF：跨栏标题、参考文献、图注、无边框表格和跨页段落。
3. 扫描 PDF：中文、英文缩写、倾斜、噪声；结构评分必须与 OCR CER/WER 分开。
4. DOCX：Heading 1/2/3、自动目录、分页符、页眉页脚、脚注、表格、图片和文本框。
5. Markdown：ATX/Setext、跳级标题、嵌套列表、GFM 表格、代码块、脚注、行内/块公式、图片链接。
6. 网页材料：静态 HTML、动态渲染页面、文章正文、导航/广告/侧栏、目录锚点、表格和代码块。

现有样本已覆盖前五类中的大部分风险：`SELF-001/002/003` 可用于 PDF 标题、双栏、页脚、脚注、表格和公式占位；`SELF-008/009` 可用于 Markdown 方言和跳级标题；公开或真实样本仍需补充网页、复杂 DOCX、真实跨页表格和 GROBID 论文样本。

## 7. 最小实验步骤

1. **固定金标准**：人工标注元素类型、标题级别、父子关系、阅读顺序、段落边界、页眉页脚/脚注、表格网格、图注/公式区域、引用链接。
2. **固定环境**：锁定工具/模型/配置/字体/渲染器版本，记录输入哈希和 `config_hash`。
3. **跑四种基线**：纯文本（Tika/PyMuPDF text）、低层坐标（PyMuPDF DICT/RAWDICT 或 pdfplumber）、结构解析（Docling/Unstructured/GROBID）、格式原生解析（python-docx/CommonMark/DOM）。
4. **统一 IR 映射**：把所有输出映射到第 4 节字段；缺失字段记为 `not_available`，不当作 0 分或成功。
5. **分版面评分**：单栏、双栏、跨页、脚注、表格、公式、网页噪声分别统计，不能只报总平均。
6. **做下游证据检查**：固定问题检索，验证标题路径、页/行/DOM 定位、bbox 和原始截图是否能回到证据。
7. **记录失败和降级**：保存原始输出、页面渲染、错误类别和回退结果；不只保存最终 Markdown。
8. **回归复跑**：解析器、模型或浏览器渲染器升级后重跑同一批样本，比较结构漂移。

建议实验编号：`TECH-STRUCT-001`（标题/目录）、`002`（双栏阅读顺序）、`003`（页眉页脚脚注）、`004`（表格/公式/图注）、`005`（DOCX/Markdown/网页）、`006`（统一 IR 和下游引用）。

## 8. 结构正确性、完整性和下游指标

### 8.1 结构正确性

- 标题检测 Precision/Recall/F1；标题文本归一化匹配率；层级准确率；父子关系准确率；目录路径一致率。
- 阅读顺序：元素 pairwise accuracy、Kendall tau 或顺序编辑距离；同时报告被正确定位元素覆盖率。
- 段落边界 Precision/Recall/F1；跨页段落合并准确率；列表项/代码块边界准确率。
- 页眉页脚误归入正文率、脚注保留率和 marker-link 关联准确率。
- 表格：表格检测 IoU/召回、行列数准确率、cell 位置对齐准确率、合并单元格 F1、单元格文本准确率、跨页 table-group 准确率。
- 图注/公式/代码块检测召回率；图注配对准确率；公式编号和引用关系准确率。
- 网页：正文区域 Precision/Recall、标题 DOM 路径准确率、导航/广告污染率、锚点可回溯率。

### 8.2 内容完整性和工程质量

- 归一化字符召回率、特殊符号/上下标错误率、列表标记保留率、原文偏移覆盖率。
- 每元素 page/bbox/line/DOM 定位完整率；引用 bbox 覆盖证据比例。
- 处理成功率、超时率、p50/p95 延迟、内存、输出大小、版本升级结构漂移。

### 8.3 用户任务指标

- 目录导航：目标章节点击后落到正确元素的成功率。
- 段落检索：命中段落位于正确标题路径的比例；页眉页脚误命中率。
- 问答：答案证据块包含正确段落/表格/公式的比例；跨章节问题是否丢失上下文。
- 引用定位：页码/行号/DOM 锚点正确率，bbox 是否覆盖引用文字，点击后是否能在原页面高亮。

## 9. 典型失败和降级方案

| 失败 | 用户影响 | 降级方案 |
|---|---|---|
| 标题被识别为正文或层级跳错 | 目录缺项/错层，章节问答上下文错误 | 保留原文和候选标题，显示平面阅读；不自动重写跳级层次 |
| 双栏交错或跨栏标题错序 | 检索命中错误段落，问答把两栏拼接 | 按栏输出页面级文本，标记“阅读顺序不确定”，允许原页核验 |
| 页眉页脚混入正文 | 每页重复内容污染索引和答案 | 保留 `header/footer` 类型，检索降权；引用仍可指向原页 |
| 脚注丢失/插入正文 | 定义、限定条件和引用关系丢失 | 独立脚注块 + marker 关系；无法识别时保留 bbox/截图 |
| 表格单元格错位/合并丢失 | 数值问答和比较结果错误 | 输出线性化文本 + 表格截图；禁止单元格级强断言 |
| 公式被当普通文字或 OCR 错误 | 数学答案、检索关键词和引用不可靠 | 保留公式图像/bbox/编号；标记“公式文本未验证” |
| 图注与图片脱离 | 图表结论无法定位 | `caption_of` 关系失败时仍保留二者同页 bbox 和原始资产 |
| DOCX 视觉页码不可复现 | 引用无法按页跳转 | 使用标题路径、段落序号、字符偏移；需要页码时固定渲染器再生成 |
| Markdown 方言不一致 | 表格、脚注、公式或代码边界丢失 | 固定 CommonMark + 明确 GFM/footnote/math 扩展，未知扩展保留原文 |
| 网页动态内容或噪声未清理 | 导航、广告进入目录和问答 | 保存渲染快照；Readability/Trafilatura 清理失败时返回正文候选和原 URL |
| 解析器超时/模型不可用 | 导入失败或等待过久 | 本地纯文本/页面图兜底，异步重试，记录版本和失败原因 |

## 10. 对目录、章节导航和后续引用的影响

| 能力 | 需要的结构字段 | 结构错误的实际后果 |
|---|---|---|
| 目录导航 | `heading_level`、`parent_id`、`heading_path`、元素 ID、目标定位 | 错层/漏项会让用户进入错误章节；无 bbox 时 PDF 只能跳页不能高亮 |
| 章节上下文检索 | 段落边界、标题路径、阅读顺序、`role` | 段落过碎导致上下文丢失；过度合并导致答案跨章节串联；页脚重复命中 |
| 表格/公式问答 | table/cell/equation 类型、网格、资产和编号 | 单元格错位会产生看似合理但事实相反的答案；公式错误会污染推理 |
| 引用定位 | page/printed label、bbox 或 line/DOM offsets、原始哈希 | 只能给出无法复核的文本片段；用户无法回到原页确认 |
| 版本复现 | source_hash、parser/model/config 版本、原始输出 | 同一文档重新解析后 block ID/答案漂移，无法解释差异 |

产品上应把“结构置信度低”传递到检索和问答：降低该块权重、提示用户查看原页，或在严格引用模式下禁止生成无证据断言，而不是静默删除低置信度内容。

## 11. 阶段性建议

1. 一期优先保证 Markdown/TXT、DOCX 基础结构和文本型单栏 PDF；统一 JSON IR 必须先于产品目录和引用接口。
2. PDF 至少保留物理页码 + bbox；双栏、脚注、表格、公式和扫描 PDF 采用受限支持和可见降级。
3. 继续保留 PyMuPDF/pdfplumber 作为低层可解释证据，Docling 作为结构候选，Tika 作为 Java 纯文本基线；不要把 Tika 扁平文本直接当作结构结果。
4. 对网页增加渲染后 DOM 与正文抽取实验；对学术 PDF 增加 GROBID/TEI 对照，验证章节和参考文献关系。
5. 待 `TECH-STRUCT-001..006` 完成并覆盖真实授权样本后，再决定是否扩展现有 `DocumentBlock` 或引入独立 `StructureElement` 模型。

## 13. 结构实验进展（2026-09-29）

在本报告初稿之后，已完成以下可复现实验：

- `TECH-STRUCT-001-R01`：DOCX、Markdown、TXT 逻辑结构基线；验证 Heading 样式、表格、CommonMark 标题跳级和 UTF-8/GB18030 回退。
- `TECH-STRUCT-002-R01`：10 份样本统一映射到实验 JSON IR，显式记录页码、bbox、标题路径、源行、字符偏移和字段完整率。
- `TECH-STRUCT-003-R01`：加入 `contains`、`table_contains_cell`、`footnote_marker_for` 等关系边，并对 PyMuPDF 低层块做人工角色评分。
- `TECH-STRUCT-004-R01`：将已有 Docling 原始导出映射到 IR；三份 PDF 均恢复 3×3 表格网格，页脚可分类，但脚注召回仍为 0；双栏样本 bbox 覆盖率为 0.6316。
- `TECH-STRUCT-005-R01`：Markdown 扩展解析；`SELF-008` 识别出 1 个表格、9 个单元格、1 个代码块、1 个公式、1 个图片和 1 条脚注关系。
- `TECH-STRUCT-006-R01`：DOCX OOXML 检查；三份样本均含显式分页符、页眉、页脚和脚注部件，但没有固定渲染器时不能承诺视觉页码。
- `TECH-STRUCT-007-R01`：静态网页 DOM 基线；识别标题、表格、代码块并将导航、广告、脚本和样式保留为噪声层。

阶段性更新后的判断：

1. Docling 是目前文本型 PDF 结构候选中最接近项目需求的方案，但双栏阅读顺序和脚注仍是主要风险；表格网格形状正确不能替代单元格文本准确率。
2. PyMuPDF 仍适合作为页码/bbox/字符证据底层，不适合直接作为语义结构结果。
3. Markdown 只有在固定 CommonMark/GFM/脚注/数学配置后，才能把扩展结构纳入验收；方言配置必须进入 `config_hash`。
4. DOCX 逻辑结构可用，但视觉页码和 bbox 必须通过受控渲染器补充，或采用标题路径、段落序号和字符偏移降级。
5. 网页材料需要采用 DOM selector/anchor 定位，而不是套用 PDF 页码模型。

当前仍未完成最终验收：真实授权网页和复杂 DOCX 样本不足，Docling 公式/脚注/跨页表格尚未完成，且目录点击、段落检索和引用高亮尚未做端到端用户任务实验。因此仍不能宣布最终结构识别方案。

### 13.1 下游定位复测

`TECH-STRUCT-008-R01` 已对固定查询执行“命中元素 → 标题路径 → 原始位置”的检查。修正 Docling table/cell 继承章节路径后，`SELF-001/002/003` 的固定查询召回、标题路径保留和页码+bbox 保留均为 `1.0`；Markdown 扩展样本的三项结果也均为 `1.0`。这只证明证据链字段没有在适配过程中丢失，不代表检索排序或问答正确。

在 `TECH-STRUCT-009-R01` 补充前，两个明确缺口是 PDF 公式独立表示和网页 selector 金标准；补充后的状态见下一节及 [`TECH-STRUCT-008-R01.md`](../../../experiments/parser-benchmark/results/text-structure/TECH-STRUCT-008-R01.md)。

### 13.2 公式与网页补充

后续 `TECH-STRUCT-009-R01` 已加入保守的 PDF 行内公式拆分：`SELF-003` 的 `Recall@k = hits / k` 被保存为带页码/bbox 的 `equation` 子元素，并标记 `verified=false`；同时仅在存在对应参考文献元素时建立 `[n]` 引用关系。该规则不是公式语义识别，复杂公式仍需单独模型或截图降级。

网页 `SELF-012` 已接入固定查询，查询召回、标题路径保留和 DOM selector 定位均为 `1.0`。这只覆盖静态 HTML 快照，动态渲染、shadow DOM、iframe 和网页版本漂移仍未验证。

因此，结构识别实验的当前状态是：静态 Markdown、基础 DOCX、文本型 PDF 和静态 HTML 已形成可复现 IR 与下游定位基线；真实复杂版式、公式语义、脚注、跨页表格、动态网页和真实用户点击链路仍未完成。

### 13.3 目录、导航与证据定位准备度

`TECH-STRUCT-010-R01` 对 `SELF-001/002/003/008/012` 执行了目录准备度和固定证据回溯检查。5 个样本均满足当前 IR 的 `toc_ready=true`；固定查询召回、标题路径保留和位置保留均为 `1.0`，静态 HTML 的 6 个 DOM selector 也全部唯一。详细表格和边界见 [`TECH-STRUCT-010-R01.md`](../../../experiments/parser-benchmark/results/text-structure/TECH-STRUCT-010-R01.md)，机器结果见 [`ir/task-score.json`](../../../experiments/parser-benchmark/results/text-structure/ir/task-score.json)。

这些数字只证明适配层没有丢失标题路径、元素 ID、页码/bbox、源行或 DOM selector；`toc_ready` 不是标题层级准确率，固定查询召回也不是开放域检索或问答准确率。当前尚未完成 UI 目录点击、真实章节检索、答案证据评测和引用高亮覆盖率，因此产品验收仍需真实授权样本与端到端用户任务。

### 13.6 外部 PDF 视觉复核与探针纠偏

对 `OPEN-010` 和 `OPEN-011` 的代表页完成了 Poppler 渲染复核，详见 [`TECH-STRUCT-014-R01.md`](../../../experiments/parser-benchmark/results/text-structure/TECH-STRUCT-014-R01.md)。视觉上 `OPEN-011` 第 1、3 页明显双栏，但简单 x 坐标聚类给出的疑似多栏比例为 `0.0`，形成假阴性；`OPEN-010` 同一文档的页面布局也在单栏封面/图文页之间变化。

### 13.9 外部 PDF 的 Docling 基线

已确认之前的隔离环境仍可用：`.venv-parser` 中的 Docling 版本为 `2.130.0`，因此本轮没有重新安装依赖。使用该环境对 `OPEN-003`、`OPEN-010` 和 `OPEN-011` 执行了显式关闭 OCR 的 Docling 解析，结果见 [`TECH-STRUCT-016-R01.md`](../../../experiments/parser-benchmark/results/text-structure/TECH-STRUCT-016-R01.md) 和 [`external-docling/summary.json`](../../../experiments/parser-benchmark/results/text-structure/external-docling/summary.json)。

三份样本均成功转换：`OPEN-003` 得到 149 个 `section_header`、19 个表格和 656 个单元格；`OPEN-010` 得到 30 个 `section_header`、3 个表格、36 个单元格、1 个脚注和 7 个图注；`OPEN-011` 得到 21 个 `section_header`、4 个表格、382 个单元格、3 个公式和 11 个图注。重要限制是 `OPEN-010` 标题出现词间连接，且 Docling 将当前标题全部标为 `level=1`；因此 Docling 输出应作为结构候选和位置证据，不能直接生成最终目录。

补充的 `TECH-STRUCT-017-R01` 使用 PDF 内嵌目录作为弱参照，计算 Docling `section_header` 与目录条目的双向重合代理，并列出未匹配项。该结果只用于发现标题候选过多、目录遗漏和词间连接问题；内嵌目录不是人工金标准，不能把重合代理解释为标题 Precision/Recall。

当前代理值为：`OPEN-003` 目录→Docling `0.9833`、Docling→目录 `0.7919`；`OPEN-010` 为 `1.0000/0.3333`；`OPEN-011` 为 `1.0000/0.8095`。三份样本的 Docling 标题层级分布仍全部为 `level=1`，而 PDF 内嵌目录具有 1-4 级或 1-2 级层次，进一步说明目录层级必须独立重建。
