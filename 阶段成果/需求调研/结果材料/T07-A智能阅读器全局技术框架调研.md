# T07-A 智能阅读器全局技术框架调研

## 文档定位

本调研只比较全局架构候选、接口和验证边界，不确定具体解析器、OCR 引擎、向量库或模型。当前没有可验证的既有系统，因此以下内容区分为：

- **原始事实**：来自官方文档、论文、公开标准或公开评测。
- **项目组解释**：将事实映射到智能阅读器场景。
- **技术/需求建议**：供 T07 和一期范围决策使用。
- **待验证/风险**：不能仅凭资料调研确定，必须通过独立实验验证。

---

## 1. 调研目标

1. 比较本地优先、云端优先和混合部署三类全局架构。
2. 明确文档从导入到引用的完整数据流。
3. 定义解析、OCR、结构识别、检索、问答、引用和多文档处理之间的模块边界。
4. 判断是否需要统一文档中间表示，以及如何支持模块替换。
5. 为敏感文档、离线阅读、检索失败和模型不可用设计降级路径。
6. 为后续 7 个局部技术调研提供接口约束、实验问题和评价指标。

本阶段不应得出“某个具体工具或模型最终入选”的结论。

## 2. 需要回答的技术问题

| 编号 | 技术问题 |
|---|---|
| GA-01 | 文档导入、解析、结构识别、索引、检索、问答和引用是否能形成可追溯数据流？ |
| GA-02 | 解析器、OCR、检索器和模型能否分别替换？替换的兼容条件是什么？ |
| GA-03 | 是否需要统一的文档中间表示，以隔离上游解析差异和下游检索/模型差异？ |
| GA-04 | 页码、章节、段落、字符偏移和版面坐标如何共同支持引用定位？ |
| GA-05 | 敏感文档和普通文档是否需要不同处理路径？ |
| GA-06 | 本地、云端和混合部署在隐私、成本、性能、维护和可替换性上的差异是什么？ |
| GA-07 | 网络不可用、检索无结果、模型不可用、OCR 质量不足时，系统如何降级？ |
| GA-08 | 哪些架构属性应在需求阶段确定，哪些应留到设计和原型阶段？ |

## 3. 候选方案类别

### 3.1 本地优先

文档、解析、OCR、索引、检索和问答尽量在本机完成，云端能力默认关闭或仅对用户明确允许的普通文档开放。

适合：

- 敏感文档；
- 离线阅读；
- 对数据出域有严格限制的场景。

主要风险：

- 本地硬件差异；
- 模型质量和响应速度可能不足；
- OCR、版面分析和多文档检索的维护成本较高。

### 3.2 云端优先

文档处理、OCR、索引或问答主要依赖远程服务，本地保留阅读器界面和少量缓存。

适合：

- 普通公开文档；
- 希望快速使用较大模型和托管服务的场景；
- 设备资源有限的场景。

主要风险：

- 文档出域和数据保留政策；
- 网络依赖；
- 按量成本和并发限制；
- 外部服务变化造成替换成本。

### 3.3 混合部署或策略路由

根据文档敏感级别、网络状态、任务类型和本地资源选择处理路径。例如：

- 敏感文档：本地解析、OCR、索引和问答；
- 普通文档：允许云端 OCR 或模型；
- 网络不可用：切换本地全文检索和缓存能力；
- 本地模型质量不足：对已脱敏片段调用云端模型。

这类架构功能和治理能力较强，但需要策略路由、双环境测试、结果一致性评估和更复杂的运维。

**项目解释**：混合部署同时保留隐私控制、离线能力和云端扩展能力，但复杂度最高。它应作为重点候选进行验证，而不是现在直接确定为最终方案。

### 5.1 建议独立的模块

以下模块应保持独立的逻辑边界：

1. 文档导入与格式识别；
2. 文档安全分类和策略路由；
3. 原生解析；
4. OCR；
5. 版面与结构识别；
6. 统一文档中间表示；
7. 分块和版本管理；
8. 全文索引；
9. 向量索引；
10. 检索与重排；
11. 问答模型适配；
12. 引用定位与校验；
13. 多文档权限过滤；
14. 降级控制和实验记录。

### 5.2 可以在部署时合并的模块

逻辑独立不等于必须部署成独立进程：

- “原生解析 + OCR 调度”可以作为一个文档处理服务；
- “检索 + 重排”可以作为一个检索服务；
- “模型调用 + 回答格式化”可以作为一个问答服务；
- 本地全文索引和向量索引可以暂时部署在同一存储组件中。

但合并不能删除接口边界，否则无法单独替换和定位失败原因。

## 6. 统一中间数据结构建议

建议定义一个版本化的 `CanonicalDocument`，作为解析、OCR、检索和问答之间的稳定契约。


### 6.3 必须保留的属性

- 稳定的 `document_id`、`document_version` 和 `block_id`；
- 原始页码和版面坐标；
- 原始文本与规范化文本的区分；
- 解析器/OCR 版本；
- 置信度和警告；
- 文档敏感级别和访问控制标签；
- 从索引片段回溯到原文块的映射。

### 6.4 重要限制

统一中间表示不是要把所有文档变成“完美语义结构”。它至少应保证：

1. 原文可回看；
2. 索引片段可定位；
3. 检索结果可追溯；
4. 问答引用可验证；
5. 上游工具变化不会直接破坏下游接口。

复杂公式、图像语义、表格合并单元格等内容可以暂时以资产引用、原始片段和置信度形式保留，不应为了追求统一而伪造结构。

## 7. 模块接口和替换规则

### 7.1 接口建议

| 模块 | 输入 | 输出 |
|---|---|---|
| 导入器 | 文件字节、文件名、用户元数据 | `DocumentEnvelope` |
| 格式识别器 | 文件头、扩展名、字节流 | 格式、语言、页数、风险提示 |
| 原生解析器 | `DocumentEnvelope` | 原始文本、页面对象、结构候选 |
| OCR 模块 | 页面图像、语言、预处理参数 | OCR 文本、块坐标、字符置信度 |
| 结构识别器 | 原始文本、OCR 块、页面图像 | 标题、段落、表格、脚注等结构块 |
| IR 适配器 | 解析/OCR/结构识别结果 | `CanonicalDocument` |
| 分块器 | `CanonicalDocument` | 带来源映射的 `Chunk` |
| 索引器 | `Chunk[]`、访问控制标签 | 全文索引、向量索引、索引版本 |
| 检索器 | 查询、文档范围、权限过滤、`top_k` | `Evidence[]` |
| 问答模型适配器 | 问题、证据、回答约束 | 草稿回答、模型元数据 |
| 引用校验器 | 草稿回答、证据和原文块 | 支持/不支持标记、引用位置 |
| 降级控制器 | 网络状态、模型状态、错误码 | 本地检索、原文浏览、拒答或重试方案 |

### 7.2 替换规则

**解析器可替换条件**

- 输出能映射到同一 `CanonicalDocument`；
- 页码、块 ID、来源位置和警告字段语义一致；
- 通过固定样本的回归测试；
- 新旧解析器版本可以并行比较。

**OCR 可替换条件**

- 输出文本、坐标、语言和置信度；
- 明确字符置信度和页面置信度的含义；
- OCR 失败时不能伪装成高质量文本；
- 低置信度内容应进入降级或人工核验流程。

**检索器可替换条件**

- 接受相同查询和权限过滤接口；
- 返回统一的 `Evidence` 结构；
- 保留文档块 ID 和排序分数；
- 允许全文、向量和混合检索并行评估。

**模型可替换条件**

- 输入均来自已记录的证据片段；
- 输出包含回答、拒答状态、引用占位符和模型元数据；
- 更换模型不应要求重做文档解析；
- 替换后必须重新评估引用正确率、无依据拒答和时延。

**索引替换条件**

- 全文索引和向量索引应有独立版本；
- 索引变更需要记录嵌入模型、分块规则和生成时间；
- 不能用不同嵌入空间的向量直接混用；
- 更换索引器通常需要重新索引，但不应重新解析原始文档。

## 8. 架构比较表

| 维度 | 本地优先 | 云端优先 | 混合/策略路由 |
|---|---|---|---|
| 隐私 | 最强，数据可不出设备 | 取决于供应商、协议和数据保留政策 | 可按敏感级别控制 |
| 离线能力 | 强 | 弱 | 可保留本地降级 |
| 初期部署 | 设备和模型准备较复杂 | 初期较快 | 需要同时准备两类路径 |
| 运行成本 | 固定设备成本，边际调用成本低 | 按量或订阅成本 | 两类成本并存 |
| 处理性能 | 受用户硬件影响 | 易获得弹性资源 | 可按任务路由 |
| 模型质量上限 | 受本地模型和硬件影响 | 可使用更大模型 | 普通任务可云端，敏感任务本地 |
| 维护复杂度 | 本地依赖、模型和版本维护 | 服务、账号、配额和供应商维护 | 最高 |
| 可替换性 | 对外部供应商依赖小 | 可能形成供应商绑定 | 需要双适配器和一致性测试 |
| 失败模式 | 资源不足、模型不可用 | 网络、限流、服务变更 | 路由错误、结果不一致 |
| 适合的文档 | 敏感、需离线材料 | 普通、公开材料 | 两者并存 |
| 当前判断 | 候选 | 候选 | 重点验证候选，但不是既定结论 |

### 8.1 敏感文档路径建议

敏感级别不是模型自行判断的结果，而应由明确的策略输入决定，例如：

- 用户手工标记；
- 工作区或组织策略；
- 文档来源；
- 授权状态；
- 是否允许外部处理。

敏感文档路径应至少禁止：

- 自动上传至云端 OCR；
- 自动发送至外部问答模型；
- 将原文写入第三方日志；
- 将全文用于未授权的模型训练或评测。

对普通文档，可以在获得授权并记录服务条款后允许云端处理。

## 9. 失败场景和降级方案

| 失败场景 | 可观察信号 | 降级方案 |
|---|---|---|
| 格式无法识别 | 文件头和扩展名冲突 | 保留原文件，提示不支持，提供原文下载或手工阅读 |
| PDF 阅读顺序错误 | 双栏文本交错、标题层级异常 | 显示原始页面，降低结构化检索能力，允许用户核验 |
| OCR 置信度低 | 字符/页面置信度低 | 标记“可能存在识别错误”，支持重新裁剪或人工核对 |
| 表格结构丢失 | 行列关系不可恢复 | 保存表格图像和原始文本，避免生成精确数值结论 |
| 公式识别失败 | 公式文本为空或异常 | 返回公式截图/页面位置，不让模型推断公式内容 |
| 检索无结果 | 全文和向量检索均未命中 | 明确告知未找到依据，不直接生成事实性答案 |
| 检索结果冲突 | 多文档结论不一致 | 分文档展示证据，要求回答区分来源和版本 |
| 模型不可用 | 超时、配额、服务错误 | 退回全文检索、证据片段和原文阅读 |
| 网络不可用 | 云端路径失败 | 切换本地索引、缓存结果或只提供原文浏览 |
| 引用无法验证 | 回答句子没有对应证据 | 删除该句、标记不确定或拒绝回答 |
| 多文档权限冲突 | 用户无权访问部分文档 | 检索前过滤，不在回答中暴露文档存在性 |
| 版本变化 | 原文更新、索引过期 | 标记索引版本，要求重新处理或使用旧版本引用 |

**关键原则**：降级后宁可只提供原文、检索结果或明确拒答，也不应以无引用的生成内容冒充可靠答案。

## 10. 最小独立实验设计

当前不应声称实验已经完成。以下是可登记的实验设计，结果应使用 `TECH-xxx` 编号记录。

### TECH-ARCH-001：统一中间表示可行性

- **目的**：验证 6 类最小样本能否统一表达。
- **样本**：文本型 PDF、双栏 PDF、扫描 PDF、Word、Markdown、表格/公式文档。
- **输入**：不同类别的候选解析输出。
- **观察**：标题、段落、页码、坐标、表格、公式、来源映射是否能进入统一结构。
- **通过条件**：每个可抽取块都能回溯到页码或原文位置；无法识别部分有明确警告。
- **结论类型**：可行、受限、失败或待验证。

### TECH-ARCH-002：全文/向量/混合检索对比

- **目的**：验证全局架构是否必须同时保留两类索引。
- **问题集**：精确关键词、同义表达、表格数值、跨段关系、不存在概念。
- **指标**：Recall@k、MRR、nDCG、目标段落命中率、错误召回率。
- **风险**：向量检索可能召回语义相似但事实不对应的段落；全文检索可能无法处理同义表达。

### TECH-ARCH-003：本地与云端路径对比

- **目的**：比较质量、时延、成本、资源占用和隐私边界。
- **控制变量**：相同样本、相同问题集、相同上下文上限和回答格式。
- **指标**：解析成功率、检索 Recall@k、引用正确率、拒答率、P50/P95 时延、单位文档成本。
- **注意**：未授权样本不得发送至云端；云端实验只能使用公开或明确授权样本。

### TECH-ARCH-004：策略路由和敏感文档隔离

- **目的**：验证敏感级别是否能决定本地/云端路径。
- **测试**：敏感样本、普通样本、网络不可用、策略配置错误。
- **观察**：是否发生未授权出域；错误路径是否可审计；是否能回退到本地能力。

### TECH-ARCH-005：模块替换回归测试

- **目的**：验证替换解析器、OCR、检索器或模型时，下游是否仍能工作。
- **方法**：对同一份文档使用两个候选实现，比较 IR 兼容性、索引重建需求和引用定位。
- **通过条件**：替换模块不会破坏下游接口；差异能归因到模块版本。

### TECH-ARCH-006：离线和模型不可用降级

- **目的**：验证无网络、云端服务超时、本地模型不可用时的用户可用性。
- **通过条件**：至少能提供原文浏览、全文检索或明确拒答；不生成无来源事实性回答。

### TECH-ARCH-007：引用链路验证

- **目的**：验证回答句子能否映射到文档、版本、页码、章节、段落和原文片段。
- **测试**：单段事实、跨段推理、表格读取、文档不存在内容。
- **指标**：引用精确率、引用覆盖率、页码正确率、原文支持率、无依据拒答率。

## 11. 验证指标

### 11.1 解析和结构

- 格式识别准确率；

## 12. 对后续 7 个局部技术调研的约束

| 局部环节 | 必须遵守的全局约束 |
|---|---|
| 文档解析 | 输出必须能映射到统一 IR；不能只返回无法定位的纯文本 |
| OCR | 必须保留页码、坐标、语言和置信度；低置信度不可伪装成正常文本 |
| 结构识别 | 标题、段落、表格、公式和脚注必须有稳定块 ID 和层级关系 |
| 检索 | 既要支持精确关键词，也要允许向量或混合检索；必须执行权限过滤 |
| 问答模型 | 输入上下文应来自可追溯证据；必须支持拒答和不确定性表达 |
| 引用定位 | 至少需要文档版本、页码、章节/段落和原文片段；坐标用于页面回显 |
| 多文档处理 | 文档 ID、版本、权限标签和来源必须进入检索与回答上下文 |

后续局部调研不能只比较“回答看起来是否流畅”，而必须比较：

- 是否产生可用中间表示；
- 是否保留来源映射；
- 是否支持离线或本地路径；
- 是否能在模块替换后维持接口；
- 失败时是否能给出可控降级。

## 13. 对一期范围和待决策事项的影响

### 13.1 需求调研阶段应确定

1. 一期支持的文档类别边界；
2. 敏感文档、普通文档和禁止外部处理文档的分类规则；
3. 是否要求离线阅读和离线全文检索；
4. 引用最低要求：文档、版本、页码、章节/段落、原文片段；
5. 无依据问题必须拒答或明确提示；
6. 解析、检索、问答和引用的质量指标；
7. 服务不可用时必须保留哪些能力；
8. 实验样本、授权状态和数据保留规则；
9. 所有实验必须有唯一编号和可追溯配置。

### 13.2 应暂缓到设计阶段

1. 具体解析器或 OCR 工具；
2. 具体向量数据库；
3. 具体嵌入模型和生成模型；
4. 具体云服务供应商；
5. 最终分块大小和重叠策略；
6. 具体本地硬件配置；
7. 微服务还是单体部署；
8. 具体缓存和队列实现；
9. 生产环境的自动扩缩容方案；
10. 模型微调、持续学习和复杂多模态能力。

### 13.3 当前不应做出的技术结论

以下结论目前证据不足，不应直接写入项目最终方案：

- “云端模型一定比本地模型准确”；
- “混合部署一定能同时满足隐私、成本和质量”；
- “某种向量检索一定优于关键词检索”；
- “OCR 能可靠处理所有扫描件、表格和公式”；
- “统一 IR 可以完整表达所有文档结构”；
- “有了 RAG 就能保证回答不幻觉”；
- “模型给出的页码天然正确”；
- “某个具体工具可直接覆盖一期所有格式”；
- “多文档问答只是单文档问答的简单扩展”；
- “只要保存引用文本，就一定能实现可靠定位”。

这些内容应标记为**待验证**或**风险**，并关联相应的 `TECH-xxx` 实验。

## 14. 结论口径示例

建议采用以下三层记录方式：

> **原始事实**：在某个 `TECH-xxx` 实验中，候选解析路径能够提取正文，但双栏样本的段落顺序出现错位。  
> **项目组解释**：该路径对复杂版面依赖较强，纯文本抽取结果不能直接作为可靠阅读顺序。  
> **技术/需求结论**：一期可将双栏 PDF 列为“有限支持”，要求保留原始页面和人工核验入口；是否扩大支持范围需等待更多样本验证。

## 15. 当前阶段结论

1. **建议把统一文档中间表示作为核心边界进行验证**，但不提前假定其可以覆盖全部复杂文档。
2. **解析、OCR、索引、检索、模型和引用应逻辑解耦**，即使一期部署时暂时合并。
3. **敏感文档应由策略路由控制处理路径**，不能由模型或第三方服务自行决定。
4. **引用校验必须独立于生成模型**，不能把模型输出的页码直接当作事实。
5. **本地、云端和混合部署都仍是候选方案**；应通过质量、时延、成本、隐私和失败恢复实验比较。
6. **一期应优先保证可追溯、可拒答和可降级**，而不是先追求覆盖所有复杂版面和所有模型能力。
