# T07 文档检索技术调研：关键词、BM25、向量与混合检索

## 文档定位与已有证据

本报告是第四个技术环节“文档检索”的首轮调研和最小实验记录。先阅读了工作区已有的全局技术框架、文档解析阶段总结、结构识别/OCR 调研和 `minimal-chain-java` 基线，得到以下边界：

- 当前没有阅读器产品检索系统；已有 Java 基线只有 Markdown/TXT + 简单关键词匹配 + 模拟回答。
- 解析实验已经证明：扁平纯文本不足以支持可靠引用，检索输入必须保留 `document_id`、版本、稳定 `block_id`、原文、物理页码、章节路径、段落和必要的 bbox/source span。
- 扫描 PDF、OCR、双栏阅读顺序、表格和公式仍有已知失败案例；本报告不把解析/OCR 的问题冒充成检索器质量。
- 本轮使用 `experiments/retrieval-benchmark/` 的离线自制多文档数据集，未上传真实资料，未调用云端服务。

最小实验结果见 [`TECH-RET-001-R01.md`](../../../experiments/retrieval-benchmark/results/TECH-RET-001-R01.md)，逐问题证据和分数见同目录 JSON。结果仅用于验证实验链路和首轮选型方向，不能作为生产验收或真实 embedding 的最终结论。

## 1. 结论摘要

一期建议采用“本地 BM25/全文检索为必备底座，向量检索作为可插拔增强，混合检索作为问答入口的默认策略”，理由是：

1. 精确词、版本号、引用编号、表格数字、中文专有名词和离线场景仍需要 BM25/全文索引；
2. 同义词、自然语言问题、跨表述的概念匹配需要向量检索；
3. 混合检索能让两种信号互补，但增加嵌入模型、向量索引、重建和调参成本；不能用“混合”掩盖权限过滤、分块或解析错误；
4. 对回答入口，必须返回证据原文和定位元数据，而不是只返回分数或向量相似度；无支持性证据时应拒答或退回原文搜索。

首期能力建议分层：

| 范围 | 一期建议 |
|---|---|
| 单文档、文本层 PDF/DOCX/Markdown/TXT | 支持 BM25/关键词；页面/章节/段落定位；结果可回看原文 |
| 单文档自然语言问法 | 在固定中文 embedding 可用并通过问题集验证后启用向量或混合；保留 BM25 回退 |
| 表格 | 允许表格标题、单元格/行线性化文本进入索引；数值关系和合并单元格先标“受限” |
| 扫描/OCR | 只有 OCR 置信度和字符/数字准确率达到门槛才进入精确检索；否则显示原页、低置信度和人工核验入口 |
| 跨文档 | 首期可做“用户明确选择的少量授权文档 + 权限预过滤 + 来源分组结果”；不承诺开放式大规模知识库问答 |
| 生成回答 | 只把带原文和定位的证据交给模型；引用校验失败时删句、标不确定或拒答 |

## 2. 三种方式的基本差异与智能阅读器适用性

### 2.1 关键词/全文检索与 BM25

简单关键词基线只检查“查询词是否出现在块中”，解释性强但不考虑词的稀有程度、词频和文档长度。BM25 是词项检索的排序函数，核心形式为：

```text
score(D,Q) = sum IDF(t) * tf(t,D)*(k1+1)
                  / (tf(t,D) + k1*(1-b+b*|D|/avgdl))
```

其中 `IDF` 抑制在很多块都出现的词，`tf` 反映词频，长度归一化避免长段落仅因词多而占优。它不理解“建立索引”和“创建索引”的同义关系，也不能仅凭词面完成跨段推理，但对“RFC 9110”“A-01”“第 3.2 节”“Recall@3”和表格数值十分可靠。中文实现需明确分词、词典、同义词和 CJK 字符/二字词策略；不能把默认英文分析器直接套在中文文档上。

### 2.2 向量检索

向量检索先用 embedding 模型把查询和块编码到同一向量空间，再用余弦相似度或内积近邻搜索。它可以把“怎么找到意思相近的内容？”匹配到“向量检索将问题和段落编码到同一表示空间”，即使查询没有复用原句。代价是：中文领域和长文档需要合适模型；模型、维度、归一化和分块改变会导致索引重建；相似但不等价的句子可能被误召回；数值、版本号和短专名往往不如词项检索稳定。

本轮 `vector_proxy` 是字符 n-gram TF-IDF 稀疏代理，只用于让实验离线可复现，不具备真正 embedding 的同义语义能力。真实选型必须使用固定中文 embedding，在同一问题集上重新测量。

### 2.3 混合检索

混合检索并行得到词项排序和向量排序，再用加权分数、RRF（Reciprocal Rank Fusion）或学习排序合并。RRF 的直观做法是对每个列表中第 `r` 名贡献 `1/(k+r)`，不要求两个系统的原始分数可比。它适合智能阅读器的“专名/数字 + 自然语言”混合查询，也能在一条查询包含章节名和概念描述时减少单一检索器的漏召回。

混合不是免费增益：要维护两套索引和版本，记录嵌入模型与分块规则，处理重复证据、权重和权限过滤；若上游解析把表格/双栏文本弄错，两套索引会共同放大错误。

### 2.4 场景比较表

| 场景 | 关键词/BM25 | 向量检索 | 混合检索 | 一期判断 |
|---|---|---|---|---|
| 精确关键词、版本号、引用编号 | 强，词面可解释 | 可能被相似但错误内容抢位 | 强，BM25 保底 | 必须保留 BM25 |
| 同义词、自然语言问题 | 弱，除非维护同义词/改写 | 强，但依赖中文领域 embedding | 强 | 混合作为问答入口候选 |
| 长段落 | BM25 受长度和分块影响 | 语义匹配较好，但过长向量语义稀释 | 需窗口/父块扩展 | 以段落块 + 邻接窗口评估 |
| 跨段落问题 | 单块命中不保证组合证据 | 可召回相关块，但不会自动完成逻辑 | 召回后按章节/邻接合并 | 检索与上下文拼接分开验收 |
| 表格内容 | 单元格/行线性化后可精确查数值 | 表格结构丢失时相似度不可靠 | 可用词项抓数字、向量抓表头语义 | 保留 table/cell/row 元数据，复杂关系降级 |
| 中文文档 | 分词/CJK 分析器决定质量；专名和数字强 | 需中文、多领域、长文本验证 | 互补最佳但维护最高 | 中文问题集必测，不能外推英文结果 |
| 多文档 | 文档过滤、字段权重清晰 | 跨表述匹配强，容易跨来源混淆 | 适合按来源分组重排 | 首期只做授权文档集合 |
| 是否包含回答所需原文 | 可直接返回词项上下文 | 默认只返回向量 ID/分数，需回表 | 两路都必须回表到 CanonicalDocument | 无原文证据不得生成事实回答 |
| 页码/章节/段落 | 索引字段可过滤和返回 | 需把 metadata 与向量一起存储 | 两套索引都要返回同一 Evidence | `Evidence` 必须含定位字段 |
| 速度 | 本地倒排查询快，索引成熟 | ANN 查询快但编码有成本 | 查询和合并成本最高 | 记录 p50/p95，不只看平均值 |
| 资源占用 | 词典、倒排表和少量存储 | embedding 计算、向量存储、ANN 索引 | 两者相加并有版本维护 | 先 BM25，再按收益启用向量 |
| 维护成本 | 低至中；分词/同义词需维护 | 中至高；模型与索引重建 | 最高；两套链路和融合参数 | 先保留可替换接口，避免绑定产品 |

## 3. 证据对象和定位契约

检索器返回统一的 `Evidence`，至少包括：

```text
document_id, document_version, source_hash
block_id, block_type, original_text, normalized_text
physical_page, printed_page_label, section_path
paragraph_index, char_start, char_end, bbox
table_id, row_id, cell_id (如适用)
retriever, index_version, score, rank, confidence/warnings
```

索引可以使用规范化文本、分词文本和线性化表格文本，但回答上下文必须回表到 `original_text`。页码要区分 PDF 物理页与文档打印页；DOCX 若没有稳定视觉页码，应返回标题路径、段落序号和字符偏移，并提示页码不可用。页眉页脚保留类型并默认降权，不要静默删除，以便原页复核。

### TECH-RET-007-R01 结果

证据契约检查了主实验产生的 95 条证据。当前完整率为 **0.000**：结果已经保留 `document_id`、`block_id`、页码、章节路径、段落号和原文，但版本、源文件哈希和字符偏移尚未进入自制数据集，因此以 `null` 明确返回。该结果不是检索排序失败，而是引用链路尚未达到可验收状态；在真实 PDF/DOCX 接入时必须从解析 IR 传递这些字段，不能用默认值伪造。详见 [`TECH-RET-007-R01.md`](../../../experiments/retrieval-benchmark/results/TECH-RET-007-R01.md)。

表格建议建立三层可检索表示：表格标题/说明、行级线性化文本、单元格值；同时保留 `table_id/row_id/cell_id` 和页面 bbox。对跨页表格、合并单元格、图像表格只在结构恢复通过时承诺精确问答，否则提供表格截图和线性化证据。

## 5. 固定问题集与最小实验设计

### 5.1 固定问题类别

至少保留以下问题类型，每类 3-5 题并人工标注相关块 ID；每题同时记录 `answerable` 和 `gold_evidence`，无答案题的 gold 为空：

| 类别 | 示例 | 主要验证 |
|---|---|---|
| 精确词 | “BM25 词频 逆文档频率 文档长度” | 精确命中和排序 |
| 同义/自然语言 | “怎么找到意思相近的内容？” | 词面不完全重合的语义召回 |
| 长段/跨段 | “为什么检索块要保留上下文并能回到原文？” | 邻接窗口、父章节和证据完整性 |
| 表格 | “哪种方式同义问法强且维护成本中高？” | 表头、行和单元格关系 |
| 中文混排 | “敏感资料没有网络时用什么索引？” | 中文分词、中文专名和英文/数字混排 |
| 多文档 | “跨文档回答前需要做什么并如何处理冲突？” | 来源分组、权限过滤和冲突展示 |
| 引用证据 | “结果为什么必须包含回答所需的原文？” | 原文支持和回溯字段 |
| 无答案 | “系统是否支持脑电波直接读取？” | 空检索/拒答，不生成猜测 |

本轮 `SELF-RET-001` 已实现上述 8 类各 1 题、3 个合成文档和 11 个内容块。它适合冒烟测试，不足以估计泛化性能。

### 5.2 对照系统

固定相同的分块、权限过滤、top-k 和证据回表逻辑，只替换检索器：

1. 关键词基线：词项是否出现；
2. BM25：固定 tokenizer、`k1/b`、字段权重；
3. 真实向量：固定中文 embedding、维度、归一化、ANN 参数；本轮用 `vector_proxy` 仅做链路代理；
4. 混合：BM25 + 向量，优先 RRF，随后再测加权融合/重排。

每次运行保存源文件哈希、解析器版本、分块规则、索引版本、embedding 模型/维度、权限过滤配置、查询文本、排名、分数、原文证据、页码/章节/段落、异常和 p50/p95 时延。

### 5.3 已完成的最小结果

`TECH-RET-001-R01` 在 7 个有答案问题上的结果：

| 方法 | Recall@3 | 命中率 | MRR | Top-3 误召回率 | 无答案误召回率 |
|---|---:|---:|---:|---:|---:|
| 关键词 | 0.857 | 0.857 | 0.857 | 0.714 | 1.000 |
| BM25 | 0.857 | 0.857 | 0.857 | 0.714 | 1.000 |
| 字符 n-gram TF-IDF 代理 | 1.000 | 1.000 | 0.929 | 0.667 | 1.000 |
| BM25 + 代理 RRF | 1.000 | 1.000 | 0.905 | 0.667 | 1.000 |

解释：当前合成问题集偏小，BM25 与简单关键词差距不明显；向量代理在同义/长段问题上更容易把相关块放入 top-3。RRF 没有超过代理的 MRR，说明“混合必然更好”不成立，融合参数和真实 embedding 仍需单独验证。修正后的无答案误召回率为 1.000：问题“脑电波直接读取”与文档中的“直接支持”发生词面重叠，四种方法都产生了非零候选。这不是要求检索器凭分数猜测答案，而是要求上层使用相关性阈值、答案可回答性判断和原文证据门槛。当前微型数据集的平均查询延迟约为 0.06-0.26 ms，不能外推到百万块索引；只可用于确认输出结构、指标和降级路径可运行。

降级动作记录见 [`TECH-RET-009-R01.md`](../../../experiments/retrieval-benchmark/results/TECH-RET-009-R01.md)：无答案时拒答/原文浏览，向量索引不可用时退回 BM25，OCR/表格结构低置信度时返回页面或表格截图，缺少定位字段时禁止进入引用型问答上下文。

### TECH-RET-010-R01：真实解析 IR 检索结果

本轮进一步直接读取已有解析实验的 IR：`SELF-001`、`SELF-002`、`SELF-003`、`SELF-005` 和 `SELF-008`，共 5 个文档、80 个块、12 个固定证据片段问题。关键词检索 Hit@3 为 **0.833**，返回证据元数据完整率为 **0.606**。PDF 样本的源哈希、物理页码、bbox 和字符偏移可回溯；Markdown/DOCX 或低层解析结果可能没有视觉页码、章节路径或字符定位，因此不能统一承诺页级引用。详见 [`TECH-RET-010-R01.md`](../../../experiments/retrieval-benchmark/results/TECH-RET-010-R01.md)。

该结果把一期范围进一步收窄：文本型 PDF 在 IR 字段完整时可以承诺“页码+bbox+原文”检索证据；Markdown/TXT 可承诺“块 ID/行号或字符偏移”，但不能虚构页码；DOCX 需要额外渲染或 OOXML 位置适配后才能承诺视觉页码。检索器的 Recall/Hit 不能掩盖上游结构和定位字段缺失。

## 6. 指标的适用方式

### 6.1 召回与排序

- `Recall@K`：对有答案问题，`gold_evidence` 至少一个相关块是否出现在 top-K；适合判断问答前“证据有没有被找回来”。若一个问题有多个必要块，另报“必要证据全部召回率”，不能只看任一命中。
- 命中率（Hit Rate@K）：每个问题是否至少命中一个相关块后取平均；与单答案 Recall@K 相近，但要明确按问题还是按文档统计。
- `MRR`：第一个相关块排名的倒数平均；适合衡量用户打开结果时第一条是否有用，不适合替代多证据覆盖率。
- `nDCG@K`：相关性有 0/1/2/3 级时评估排序，例如“直接回答原文”高于“同章节背景”；适合长段、表格和跨段问题。
- Precision@K/Top-K 误召回率：结果中无关块的比例；适合测量上下文窗口污染和模型被错误证据带偏的风险。
- 无答案误召回率：`answerable=false` 的问题是否仍返回高分内容；它直接决定是否需要拒答阈值和原文浏览降级。

### 6.2 证据、定位和系统性能

- 原文支持率：进入回答上下文的证据是否包含参考答案所需的完整原文，而不是只包含相似标题。
- 引用定位完整率：检索结果能否同时回到 `document_id/version + page + section_path + paragraph/block + original_text`；PDF 可加 bbox，DOCX 无视觉页码时用段落/字符偏移。
- 表格结构命中率：相关单元格、行、表头是否一起召回；不能只看某个数字 token 命中。
- 权限过滤正确率：无权文档不得进入 top-K，也不得通过错误信息泄露其存在性。
- 延迟：分别记录索引构建、查询编码、ANN/倒排查询、融合和回表的 p50/p95；平均值不足以描述交互体验。
- 资源：索引磁盘、内存、embedding 计算时间、批量吞吐、CPU/GPU 峰值；记录每百万块或每 GB 文档的归一化值。
- 维护：索引重建时间、模型/分块/同义词词典变更导致的结果漂移、版本回滚可行性。

## 7. 误召回、漏召回和排序错误

| 类型 | 典型原因 | 智能阅读器中的表现 | 修正或降级 |
|---|---|---|---|
| 误召回 | 常见词 IDF 低但仍占位；页眉页脚重复；OCR 形近字；向量把相似概念当同一事实；表格线性化丢行列关系 | top-k 被目录/页脚、相邻概念、错误数字占据 | 字段权重/类型降权、去重、表格结构化、原页核验、混合重排 |
| 漏召回 | 同义词、中文分词、专名/版本号切分错误；块过短；跨段关系分开；OCR 漏字；权限过滤过严 | 问题相关段落存在但不在 top-k | 同义词/查询改写、中文 char+word 分析、父块/邻接窗口、OCR 模糊搜索、提示用户扩大文档范围 |
| 排序错误 | BM25 长度偏置或字段权重不当；向量模型领域不匹配；融合分数不可比；相关块分数相近 | 相关证据在第 5 条以后，模型只看到背景块 | RRF/学习重排、按块类型和标题加权、扩大候选 K 后重排 |
| 引用错误 | 索引只存文本副本，未存稳定 block/page；解析版本变化；表格/双栏阅读顺序错误 | 回答看似正确但页码/章节不对 | source hash、版本化 IR、引用校验失败即删句/拒答 |
| 空检索误判 | 把“没有召回”当成“文档没有答案”；阈值过高或问题超出范围 | 用户得到武断“没有”或模型开始猜 | 区分 `no_match`、`low_confidence`、`not_indexed`、`permission_filtered`，提供原文浏览/改写/扩大范围 |

## 8. 检索失败的降级策略

1. **查询无命中**：先用规范化、同义词和中英文/数字变体重试；仍无命中则明确“未找到支持性原文”，提供当前文档全文/目录搜索，不生成事实答案。
2. **BM25 无命中、向量可用**：展示向量结果但标记“语义相似、需核验原文”；回答必须通过原文证据门槛。
3. **向量模型/索引不可用**：退回 BM25/关键词；不因为缺少语义索引而阻断单文档阅读。
4. **OCR 低置信度**：页面级关键词/模糊匹配 + 原图裁剪 + 字符置信度；数字、单位、版本号不通过精确问答门槛。
5. **表格结构失败**：返回表格截图、表格标题和线性化文本；不承诺行列关系或精确数值结论。
6. **跨段证据不足**：扩大到同章节父块/前后邻接块，展示多段证据；无法闭合条件和结论时拒答。
7. **多文档冲突**：按文档/版本分组展示，不平均拼接；回答明确指出冲突来源和日期。
8. **权限或版本问题**：检索前过滤权限，标记索引版本过期并要求重建；不要通过“未找到”泄露不可见文档。
9. **全链路失败**：保留原文件、错误码和可见页面阅读；返回“未建立可靠文本证据”，而不是空白或猜测。

## 9. 一期单文档与跨文档范围影响

### 单文档

可把质量目标定得更明确：固定文档范围、固定权限和固定版本，优先保障精确查找、章节导航、原文片段、页码/段落定位和离线 BM25。自然语言问答可采用混合候选，但必须保留“只展示证据”的模式。单文档不代表可以忽略跨段：分块需有父章节和邻接窗口，但回答引用仍逐块可追溯。

### 跨文档

跨文档增加了文档级召回、权限过滤、来源冲突、版本新旧、重复内容和索引规模问题。一期不建议承诺“任意工作区全部文档的无监督问答”；建议限定为用户明确选择的少量授权文档，结果按 `document_id/version` 分组，先做文档级过滤/召回再做块级混合检索。只有完成权限泄露测试、冲突问题集和跨文档引用覆盖测试，才扩大范围。

### TECH-RET-008-R01 续做结果

已用同一批合成文档执行 4 个权限案例：允许单文档、允许两个文档、相关证据位于不可见文档、以及跨文档问题但只允许一个文档。四种检索方式均达到 **未授权泄露率 0.000、全部通过**，有答案案例命中率为 **1.000**。结果见 [`TECH-RET-008-R01.md`](../../../experiments/retrieval-benchmark/results/TECH-RET-008-R01.md)。

该结果只证明“过滤可以在实验链路中执行”，并没有证明系统自动知道“无答案”。两个不可见证据案例中，检索器仍可能返回允许范围内的无关块；生产实现需要同时设置相关性阈值/拒答分类，并把 `permission_filtered` 与 `no_match` 分开记录，避免把“看不到”误报为“文档没有答案”。

## 11. 现阶段决策与待验证项

当前可作出的阶段性决策是：全文/BM25 是一期必须能力；向量检索不是替代全文，而是针对自然语言和同义表达的可插拔增强；混合检索值得进入原型，但不能在真实中文、表格、OCR、跨段和权限问题集完成前宣称最优。

真实 embedding 的初次门禁记录为 `TECH-RET-003-R01`（当时因模型下载失败而阻塞），随后通过禁用失败的 Xet/证书链路径并使用可断点的直接 HTTPS 下载解决。`TECH-RET-003-R02` 已通过：固定模型 `BAAI/bge-small-zh-v1.5`，revision `7999e1d3359715c523056ef9478215996d62a620`，512 维、L2 归一化、CPU 编码。在同一 `SELF-RET-001` 上，真实向量 Recall@3/命中率均为 1.000，MRR 0.857；BM25+真实向量 RRF Recall@3/命中率均为 1.000，MRR 0.905；两者 Top-3 误召回率均为 0.667，无答案误召回率均为 1.000，平均查询约 11.3 ms。该数据集很小，只解除模型链路阻塞，不能外推生产规模或领域泛化。新增 `TECH-RET-011-R01` 复用现有 Tesseract OCR 和结构 IR：OCR 固定查询页 Hit@3 为 1.000、结构 IR Hit@3 为 1.000、OCR 证据页码携带率为 1.000；其中结构 IR 的部分样本缺视觉页码，仍需按字段能力降级。仍待验证：表格/跨页表格结构；多文档权限和版本冲突；百万级文档块的内存、索引构建和 p95；以及生成回答的引用支持率。任何一期“支持”结论都应附样本哈希、工具/模型版本和对应 `TECH-RET-xxx-Rxx` 记录。
