# T07 第六个技术环节：回答引用和原文定位技术调研

## 文档定位

本报告研究“AI 回答如何关联到可核验的文档依据”，对应决策 **D05**。当前项目尚未实现产品级引用机制，因此本报告不把某个模型或服务的引用字段当作最终方案，而是定义证据契约、定位锚点、校验方法、交互和降级边界。

引用的目标不是在回答末尾添加一个页码，而是让用户能够回答三个问题：

1. 这句话由哪一份文档、哪个版本支持？
2. 用户能否一键回到原文并看到被引用的范围？
3. 原文不支持、定位不唯一或多个来源冲突时，系统是否停止生成或明确提示？

## 4. 引用粒度比较与推荐组合

| 粒度 | 优点 | 风险/不适用场景 | 一期建议 |
|---|---|---|---|
| 物理页码 `page_number` | 易实现、用户熟悉、可做粗粒度跳转 | 封面/罗马页码、插页、OCR 页面、页面重排；不能证明句子在该页支持回答 | 必存，不能单独作为验真依据。 |
| 印刷页码 `page_label` | 与纸质引用一致 | 文档可能没有标签，标签重复或与 PDF 物理页错位 | 与物理页分开存，缺失时为 `null`。 |
| 章节/标题路径 | 语义稳定，适合 DOCX/Markdown 和导航 | 重复标题、标题解析失败、跨页标题、版本改名 | 必存 `section_path[]`，显示为辅助定位。 |
| 段落/`block_id` | 适合检索、审计和权限过滤 | 分块规则变更会改变 ID；跨段回答要多个 block | 必须有稳定 ID 和版本；作为主引用对象。 |
| 原文片段 quote | 用户可直接核验，跨格式通用 | 片段重复、OCR 错字、规范化造成漂移、过短片段语义不完整 | 存 exact + prefix/suffix + quote hash；优先用于恢复。 |
| 字符偏移 | 机器精确、可自动校验 | 依赖规范化文本和解析版本；Unicode/OCR/换行变化会失效 | 存 `char_start/end`，必须绑定 source hash/version。 |
| 页面 bbox/多边形 | PDF/图片高亮直观，适合视觉核验 | 旋转、裁剪、缩放、双栏阅读顺序和 OCR 框错误 | PDF/扫描件可选但优先支持；不能替代文本支持检查。 |

**推荐一期组合**：`document_id + document_version + source_hash + block_id + section_path + paragraph_index + physical_page + page_label + quote + char_start/end`；PDF/图片再加 `bbox[]`、`coordinate_system`、`page_rotation`。页码是导航字段，quote/offset 是文本校验字段，bbox 是视觉回显字段。

  "source_hash": "sha256:...",
  "source_name": "实验报告.pdf",
  "source_access": "allowed",
  "block_id": "doc-abc-e0017",

  "paragraph_index": 17,
  "physical_page": 12,
  "page_label": "8",

  "quote_prefix": "本轮结果显示，",
  "quote_suffix": "，但元数据仍不完整。",
  "char_start": 1832,

回答也应结构化保存：`answer_id`、`question`、`claims[]`、`citations[]`、`answer_status`（`answered/refused/needs_human_review/partial`）、`evidence_set_id`、`retrieval_index_version`、`model_version`、`verification_summary`。模型只能返回 `citation_id`，不能自行编造页码；服务端将 citation ID 映射到检索证据并二次校验。

## 6. 定位和核验算法

### 6.1 定位顺序

1. 用 `source_hash + document_version + block_id + char_start/end` 做精确查找。
2. 精确查找失败时，用 `quote exact + prefix + suffix` 做唯一匹配。
3. 允许有限规范化：Unicode NFC、空白/换行归一化、连字符归一化；OCR 常见差异只能作为 `recovered`，不能静默覆盖。
4. 若出现多个匹配、quote 过短、版本不同或坐标越界，状态为 `ambiguous/stale/invalid`，不生成可点击的“精确高亮”。
5. 高亮前校验 bbox 所在页、旋转和坐标系；无法证明框覆盖 quote 时降级到页面或 block。

### 6.2 回答支持性

把回答拆成原子陈述 `claim_i`，每条标为：

- `entailed`：原文直接支持；
- `partially_supported`：只支持部分范围/条件；
- `contradicted`：来源明确相反；
- `not_supported`：检索到但不能推出；
- `unverified`：定位或文本质量不足。

只有 `entailed` 才允许无警告呈现；`partially_supported` 必须缩小措辞或加限定语；`contradicted` 进入冲突展示；`not_supported/unverified` 删除、标不确定或拒答。数值、日期、因果、否定词和比较级要单独作为高风险 claim 检查。

### 6.3 推荐指标

```text
citation_precision = 支持该 claim 的 citation 数 / 展示 citation 数
citation_recall = 被正确引用的金标准证据数 / 金标准证据数
claim_support_rate = entailed claims / 全部可核验 claims
locator_exact_rate = exact 定位成功引用 / 全部引用
page_accuracy = 正确物理页引用 / 页码引用
highlight_iou = 高亮框与人工金标准框的 IoU
source_distinction_accuracy = 正确区分文档/版本的回答数 / 跨文档题数
unsupported_abstention_rate = 正确拒答或转人工的无依据题 / 无依据题
```

字段完整率只能作为门禁，不能代替以上质量指标。`TECH-RET-007-R01` 的完整率 0 应继续作为阻断问题记录。

## 7. 用户跳转和核验交互

- 回答中的每条 claim 旁显示短 citation 标记；点击后打开对应文档版本、物理页和章节路径。
- PDF/扫描件优先滚动到页并绘制 bbox；文本视图同时高亮 quote；高亮失败时显示 block 和“仅定位到页面/段落”。
- 展开引用卡片显示来源文件名、版本、页码、章节、原文片段和定位状态；默认不把整页塞进回答。
- 多份文档按来源分组，显示版本和更新时间；冲突时并列展示，不合并成一个无来源结论。
- 用户可从引用跳回回答 claim，也可从原文“返回回答”；应保留当前页、缩放和高亮状态。
- 引用状态要显式区分“已精确定位”“经规范化恢复”“仅页级”“定位失效”，不要用同一种链接外观掩盖不确定性。

## 8. 页码偏移、引用不准确与原文不支持

### 常见原因

1. PDF 物理页从 1 开始，而印刷页从封面后或罗马数字开始；只保存一个 `page` 会产生偏移。
2. 解析器去掉页眉页脚、合并换行或改变双栏阅读顺序；字符偏移随版本漂移。
3. DOCX 的视觉分页依赖字体、渲染器、纸张和页边距；没有稳定物理页时不应伪造页码。
4. OCR 文字错误、表格线性化和公式/脚注顺序错误，使 quote 看似命中但语义不支持。
5. 多文档同名、同标题、同一版本不同副本；只传文件名或标题会错源。
6. 生成模型从上下文“猜”页码或引用了检索到但不支持 claim 的相邻段落。

### 处理规则

- 所有页码同时存物理页和印刷标签；显示时注明类型。
- 所有引用绑定 `source_hash` 和解析器/索引版本；版本变化标记 stale。
- quote 不唯一、offset 越界、bbox 无法覆盖或原文支持性不足时，不生成精确跳转。
- 无依据问题返回“在当前文档和版本中未找到可支持原文”，可提供检索结果、改写问题或原文浏览入口。
- OCR/表格/公式低置信时显示原页/截图和警告，禁止生成精确数值或公式结论。
- 跨文档冲突不强行投票；列出来源、版本、时间和冲突字段，状态为 `needs_human_review`。

## 9. 最小实验问题集

使用现有 `SELF-001` 至 `SELF-008`、Markdown/TXT、单栏/双栏/扫描 PDF、表格/公式和两份内容相近的文档，固定以下问题：

| 编号 | 问题类型 | 必须检查 |
|---|---|---|
| C01 | 单段直接事实 | claim、quote、block、页码均精确。 |
| C02 | 同义表达 | 检索可命中，但引用仍必须来自支持性原文。 |
| C03 | 跨段落关系 | 是否返回多个 citation，是否错误压缩成一个段落。 |
| C04 | 表格单元格数值 | 行列、bbox 和数值文本一致；低置信则拒答/提示。 |
| C05 | 双栏跨栏标题 | 阅读顺序、标题路径、页码和高亮不交错。 |
| C06 | 扫描/OCR 中英文数字 | CER/WER、quote 和原图核验；禁止只凭关键词命中。 |
| C07 | DOCX 无稳定视觉页 | 使用章节、段落、offset，不伪造页码。 |
| C08 | 多文档同名事实 | 每个 claim 绑定正确 `document_id/version/hash`。 |
| C09 | 版本更新后旧引用 | 显示 stale，不能静默跳到新文本。 |
| C10 | 原文不存在的事实 | `refused`，不得引用相似但不支持的片段。 |
| C11 | 两文档互相冲突 | `needs_human_review`，并列来源和差异。 |
| C12 | 文档内提示注入 | 文档内容不获得指令权限；引用只证明文本，不改变系统策略。 |

## 10. 常见引用错误分类

| 错误 | 原因 | 检测/修复 |
|---|---|---|
| 页码整体偏移 | 物理页与印刷页混用、封面/插页 | 双字段存储；用人工页金标准验收。 |
| 引用存在但不支持 claim | 只检查 citation ID 是否来自检索结果 | claim-level entailment/人工评分；必要时改写或拒答。 |
| 高亮错句 | offset 基于不同规范化文本或版本 | source hash + quote/prefix/suffix 恢复；多匹配即失败。 |
| 双栏串栏 | 阅读顺序和 bbox 排序错误 | 页面/栏级人工标注；失败则按列或页级降级。 |
| OCR 错字但关键词命中 | 关键词短、置信度未传递 | CER/WER、字符级金标准、原图核验。 |
| 表格数值错行 | 线性化丢失行列关系 | 保留 cell/bbox；结构失败不回答精确数值。 |
| DOCX 页码不稳定 | 渲染器/字体环境不同 | 优先章节、段落和 offset；页码标为 unavailable。 |
| 多文档串源 | 只用文件名/标题 | `document_id/version/hash` 作为主键；权限先过滤。 |
| 版本漂移 | 原文更新后继续使用旧 offset | stale 检测，要求重新处理或打开旧版本。 |
| 模型伪造引用 | 自由生成页码/URL | 模型只返回服务端 citation ID，服务端白名单校验。 |

## 11. 引用失败时的降级方案

1. **精确高亮失败，block 可定位**：显示章节、段落和原文，不承诺坐标。
2. **block 失败，页可定位**：打开物理页/印刷页标签并提示“仅页级定位”。
3. **页码不可用，文本可定位**：使用标题路径、段落序号和 quote；适用于 DOCX/Markdown。
4. **quote 漂移但唯一恢复**：显示“已按文本恢复”，保存恢复方法和差异。
5. **OCR/表格低置信**：展示原页或截图、警告和人工核验入口；禁止精确事实回答。
6. **来源冲突**：并列展示文档/版本/时间，转人工复核，不做无依据综合。
7. **检索有词面命中但无支持**：停止生成事实回答，提示未找到支持性原文，并允许改写问题。
8. **全部定位失败或权限不足**：拒答；不能泄露被过滤文档的存在性。

## 12. 对 D05 和一期验收指标的影响

### D05 建议决策

一期采用“组合引用 + 服务端校验”而不是页码单点引用：

- 最低可交付：来源文件/文档 ID、版本或源哈希、block/段落、原文片段、回答 claim 绑定关系。
- PDF/图片增强：物理页、印刷页标签、bbox、页面旋转和页面高亮。
- DOCX/Markdown：章节路径、段落索引、字符偏移和 quote；没有稳定视觉页时明确显示页码不可用。
- 生成模型不允许自由输出页码；只能引用检索证据白名单中的 `citation_id`。
- 原文不支持、引用不唯一或来源冲突时，回答状态必须为 `refused`、`partial` 或 `needs_human_review`。

### 一期建议验收口径

先在固定授权样本和 C01-C12 上验收，再确定数值门槛。建议分层记录而不是用一个总分掩盖失败：

| 指标 | 建议门槛/口径 |
|---|---|
| 必填字段完整率 | 生产候选证据 **100%**；缺字段不得进入有引用保证的回答。 |
| citation precision | 直接事实题建议 **>= 0.95**；低于门槛显示警告或收窄范围。 |
| claim support rate | 一期回答中可核验 claim 建议 **>= 0.90**；关键数值/日期/因果需更严格。 |
| locator exact rate | 支持的文本型样本建议 **>= 0.95**；恢复定位单独统计。 |
| page accuracy | 仅对有稳定页映射的格式统计；不能用 DOCX 不稳定页码稀释。 |
| unsupported abstention rate | 无依据题建议 **>= 0.95**；漏答优于编造。 |
| multi-document source accuracy | 跨文档题建议 **>= 0.95**；冲突题必须能转人工复核。 |
| 高亮覆盖率 | 有 bbox 金标准的 PDF/图片单独统计 IoU/覆盖率；不得用“页码命中”替代。 |

这些是一期候选验收指标，不是当前已达成结果。现有 `TECH-RET-007-R01` 完整率 0、`TECH-RET-010-R01` 元数据完整率 0.606，应标为当前阻断/待修复，而不是通过。

## 14. 结论

一期不应承诺“模型给出的页码天然正确”，也不应把单一粒度作为可靠引用。建议先完成 `TECH-CIT-001/003/006/010/011`，建立证据白名单、quote/offset 校验和无依据拒答；随后对支持格式补做页码、章节和 bbox 的用户核验实验。当前最可靠的产品表述是：**回答中的每个可核验陈述都应关联到版本化原文证据；定位精度会因文档格式和解析质量不同而分层，并在失败时明确降级。**

已复用现有解析 IR 的 80 个内容块完成首轮实验。结果汇总见 [`TECH-CIT-EXPERIMENTS-R01.md`](../../../experiments/retrieval-benchmark/results/TECH-CIT-EXPERIMENTS-R01.md)，运行器为 [`run_citation_experiment.py`](../../../experiments/retrieval-benchmark/run_citation_experiment.py)。
