# TECH-DOC-007-R02 人工标注结构评分

日期：2026-09-24  
范围：三份项目自制文本型 PDF；不执行 OCR，不评估检索或问答。

## 1. 标注和评分口径

`SELF-001`、重新生成的 `SELF-002`、`SELF-003` 均由用户通过自然语言确认结构，再回填为 `manual-annotations/SELF-*.json`。每份标注包含阅读顺序、标题级别、自然段、表格网格、脚注、页脚、物理页和 bbox；`SELF-003` 另含行内公式。

- 字符召回：NFKC、大小写折叠、去空白，并排除人工表格展示分隔符 `|` 后按字符多重集计算。
- 阅读顺序：只比较完整定位成功的非表格单位；必须同时查看单位覆盖率。本批次覆盖率均为 1.0。
- 段落边界：完整人工自然段必须作为一个解析元素出现；这是严格的边界召回，不是段落语义相似度。
- 标题、脚注、表格：只有解析器显式提供相应类型或网格时才评分；字段缺失记为 `not_available`。
- 页脚：分别记录原始输出是否包含页脚，以及能否通过显式类型过滤从下游正文排除。

原始评分见 `manual-score.json`，评分脚本为 `scripts/score_manual_structure.py`。

## 3. 原始事实（F）

- 三个解析器在三份样本上的归一化字符召回均为 1.0。
- PyMuPDF 的所有文本 block 均有物理页和 bbox，但没有标题、脚注或表格网格类型。
- PyMuPDF 在双栏 `SELF-002` 上将多个自然段按视觉行拆成 block，严格段落边界召回为 0.2857。
- Docling 的所有已输出元素均有页和 bbox，并提供标题和表格网格。
- Docling 在 `SELF-001` 和 `SELF-003` 中把文档标题放到正文序列靠后位置，非表格单位顺序准确率为 0.6667；新版双栏样本为 1.0。
- Docling 将文档标题计入 section header，三个样本标题 F1 分别为 0.8、0.9091、0.8。
- Docling 未将三份灰色脚注标为脚注，脚注召回均为 0。
- Docling 在 `SELF-002` 的 9 个表格单元格中错拼 2 个，单元格文本准确率为 0.7778；另外两份为 1.0。
- Tika 在这些样本上保留扁平文本顺序和大部分段落分隔，但不提供元素级页码、bbox、标题、脚注或表格网格。
- PyMuPDF 和 Tika 的原始文本均包含页脚且没有可直接用于过滤的家具类型；Docling 可按 `page_footer` 类型过滤当前已识别页脚。

## 4. 项目组解释（I）

1. 文本完整不等于结构正确。本批次字符召回没有区分度，但结构指标已显示明显差异。
2. PyMuPDF 适合保存可解释的页和坐标证据；其 block 不能直接当作自然段，尤其不能在双栏或自动换行处直接切分检索块。
3. Docling 提供本轮最丰富的结构字段，但需要对标题位置、标题/文档标题类型、脚注和表格单元格做校验及降级。
4. Tika 可作为 Java 原生纯文本/元数据基线，但缺少支撑页内引用和结构问答的元素字段。
5. Docling 的页脚类型可用于下游过滤，但原始结构中仍应保留这些元素，不能在解析阶段无痕删除。

## 5. 技术和范围结论（C）

- 当前证据继续支持“低层坐标解析 + 结构解析 + 原始结果保留”的组合验证方向，不支持单一解析器直接承担所有格式和引用要求。
- 一期文本型 PDF 至少应保存物理页和 bbox；仅使用 Tika 扁平文本不足以满足页内引用定位。
- PyMuPDF block 必须经过段落合并或结构解析，不能直接作为最终检索块。
- Docling 的标题、脚注和表格结果需要规则校验；当表格网格不可信时应降级到原始文本、bbox 和页面截图，而不是静默输出错误单元格。
- 本轮只有三份自制 PDF，不能据此确定最终选型，也不能外推到真实论文、合同、长文档或其他字体编码。

## 6. 风险和待验证项（R）

- 增加真实授权文本型 PDF，覆盖真正密集双栏、跨页表格、脚注区域和不同字体编码。
- 为 pdfplumber 保存独立全文和表格网格输出后，使用同一金标准评分；当前结果不能用 PyMuPDF 文本代替 pdfplumber 评分。
- 对 DOCX、Markdown、TXT 建立相同的人工结构和引用定位金标准。
- 设计解析器组合前，先定义标题、脚注、表格和页脚冲突时的优先级与置信度规则。
- OCR、扫描 PDF、CER/WER 和 OCR bbox 继续留在下一调研环节。
