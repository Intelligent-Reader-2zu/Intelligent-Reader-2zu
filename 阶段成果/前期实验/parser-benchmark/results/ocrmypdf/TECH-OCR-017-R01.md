# TECH-OCR-017-R01 OCRmyPDF 本地可搜索 PDF 实验

> 本实验评价 PDF 封装、原页保留和可搜索文本层，不把 OCRmyPDF 当作新的识别模型。识别后端仍是 Tesseract。

- 样本：`SELF-004` 两页，SHA-256 `ab008a1879ed22c5f92abe0dab30f1bbd2ffe2e462b1b2c25ec55cc7fa03fa63`
- OCRmyPDF：`17.12.1`；Tesseract：`5.5.3.20260724`；语言：`chi_sim+eng`
- 成功配置：`--pdf-renderer sandwich --deskew --force-ocr`
- 运行时间：约 `3471.88 ms/文档`（两页单次运行，不是 p50/p95）
- 输出：`SELF-004-searchable.pdf`，SHA-256 `488808c5be85ac749cc25742e7b4231a830a9d8231ddf82918f9db5bf9dd9979`

## 结果

| 项目 | 结果 |
|---|---|
| 页数 | 原文件 2 页，输出 2 页 |
| 页面尺寸 | 两页逐页一致；第一页 `793.92 x 1122.72 pt`，第二页 `821.76 x 1141.92 pt` |
| 视觉 | 已渲染检查全部页面；未见裁切、重叠或内容缺失，原始第二页轻微倾斜仍可见 |
| 文件大小 | `254860 -> 119916 bytes`，本次约减少 53% |
| 英文/数字检索 | `OCR TEST`、`12345`、`A-01`、`0.95`、`page label` 可由 `pypdf` 提取命中 |
| 中文检索 | `pypdf` 提取为乱码，固定中文查询不可用 |
| bbox/结构 | 生成的是 PDF 文本层，不提供统一 JSON 区域、表格单元格或公式结构 |

## 失败路径与解释

1. 默认/自动渲染路径解析中文 hOCR 时出现 `XML ParseError: invalid token`，与当前 Unstructured 中文 hOCR 失败属于同类风险。
2. 改用 `sandwich` 后成功生成有效 PDF/A 并保留原页视觉，但中文 ToUnicode/文本提取仍不可接受。文件“看起来正常”不能证明中文检索和引用可用。
3. `--clean` 需要额外的 `unpaper`，当前未安装；去掉该增强项不影响本次封装验证。
4. 日志称两张页面图像未被优化器处理并原样保留，输出仍有效；文件体积变化不应作为 OCR 质量指标。

## 项目结论

当前 OCRmyPDF 可作为“原图不丢失、生成可搜索 PDF”的实验性封装器，但不能进入一期中文检索主路径。若使用，只能把原 PDF/页图作为证据源，并在入索引前另行验证文本层的中文解码、关键字符串召回和 bbox 可回溯；中文乱码时应回退到已验证的 JSON/TSV OCR 输出，而不是索引该文本层。
