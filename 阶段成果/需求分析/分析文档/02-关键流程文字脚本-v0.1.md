# 智能笔记助手需求分析｜关键流程文字脚本 v0.1

- 项目：智能笔记助手
- 阶段：需求分析
- 版本：v0.1
- 编制时间：2026-10-23
- 用途：作为三张关键时序图的消息脚本母版

## 1. 使用说明

1. 本文档先写“谁和谁交互、按什么顺序发生”，不急着补 UML 细枝末节。
2. 每条流程先保证**主成功路径可讲清**，异常分支只补关键节点，不展开所有错误码。
3. 时序图绘制时，参与者名称优先沿用本文档，不要临时另起新名。

建议统一采用的参与者类型：

- 参与者：用户
- 边界对象：客户端、检索界面、笔记界面
- 控制对象：导入控制器、检索控制器、笔记控制器
- 实体对象：文档、笔记、批注、标签、分享链接、索引、回答结果、引用等

## 2. 流程一：文档导入与索引

### 2.1 流程目标

把用户选定的外部资料稳定导入系统，并形成后续可检索、可引用、可追溯的文档资源。

### 2.2 主要参与者

1. 用户
2. 客户端
3. 导入控制器
4. 文档空间
5. 文档
6. 文档版本
7. 解析任务
8. 索引任务
9. 索引
10. 通知

### 2.3 主成功路径

1. 用户在客户端选择工作区与文档空间，提交待导入文件。
2. 客户端向导入控制器发送“导入文档”请求，并附带文件来源与导入范围。
3. 导入控制器校验文件格式、大小、权限与去重条件。
4. 系统在文档空间中登记文档，创建文档记录。
5. 系统为本次导入生成文档版本，并保存来源哈希、导入时间等基础信息。
6. 导入控制器发起解析任务，对文档执行文本抽取、结构识别与内容切块。
7. 解析任务完成后，系统生成内容块集合，并写回文档版本的处理状态。
8. 导入控制器发起索引任务，为该文档版本建立全文/语义索引。
9. 索引任务完成后，系统生成索引对象，并将文档标记为“可检索”。
10. 系统生成导入完成通知，告知用户该文档已完成入库。

### 2.4 关键状态变化

| 对象 | 状态变化 |
|---|---|
| 文档 | 已登记 -> 可管理 |
| 文档版本 | 新建 -> 已解析 -> 已索引 |
| 解析任务 | 待处理 -> 处理中 -> 成功/失败 |
| 索引任务 | 待处理 -> 处理中 -> 成功/失败 |
| 索引 | 未建立 -> 已建立 -> 可用 |

### 2.5 关键业务约束

1. 导入成功不等于可检索，必须在解析与索引完成后才算真正“入库完成”。
2. 文档版本必须保留来源与时间信息，以支持后续引用回溯。
3. 若文档失效、撤权或被删除，后续索引与引用要能传播失效状态。

### 2.6 时序图建议消息

1. `选择导入文件()`
2. `提交导入请求()`
3. `校验导入条件()`
4. `登记文档()`
5. `创建文档版本()`
6. `启动解析任务()`
7. `回写内容块()`
8. `启动索引任务()`
9. `生成索引()`
10. `发送入库完成通知()`

### 2.7 关键异常分支

1. 文件格式不支持：拒绝导入，返回失败原因。
2. 解析失败：文档已登记但不可检索，通知用户待复核。
3. 索引失败：允许保留原文阅读，但检索能力降级或不可用。

## 3. 流程二：笔记保存与导出

### 3.1 流程目标

把用户在原文或回答上形成的记录，稳定保存为可回溯的笔记，并在授权范围内导出或生成分享入口。

### 3.2 主要参与者

1. 用户
2. 笔记界面
3. 笔记控制器
4. 内容块
5. 笔记模板
6. 笔记
7. 批注
8. 标签
9. 引用
10. 回答结果
11. 分享链接
12. 通知

### 3.3 主成功路径

1. 用户在原文中选中内容并发起“保存为笔记”，笔记界面提交保存意图（选区、原文定位、可选模板）。
2. 笔记控制器向内容块校验原文定位是否有效。
3. 定位有效时，笔记控制器读取笔记模板的字段与输出格式；无模板时取默认。
4. 系统创建笔记对象，写入正文、类型与定位锚点。
5. 系统按需写入批注，并绑定标签、关联引用。
6. 若笔记引用了回答结论，则由引用向回答结果核验结论来源与定位。
7. 系统生成保存成功通知，告知用户笔记已保存。
8. 用户选择笔记范围发起导出或分享，笔记界面提交导出请求（范围、格式）。
9. 笔记控制器收集笔记及其批注、标签，汇总引用与原文定位。
10. 引用校验通过后，系统创建分享链接，并生成导出完成通知，提供带引用的导出结果与分享入口。

### 3.4 关键状态变化

| 对象 | 状态变化 |
|---|---|
| 笔记 | 未保存 -> 已保存 -> 已打标/已关联引用 |
| 批注 | 未创建 -> 已创建 |
| 引用 | 未关联 -> 已关联 -> 已核验/失效 |
| 分享链接 | 未创建 -> 已生效 -> 已过期/已撤销 |

### 3.5 关键业务约束

1. 保存笔记不等于“把一段文字复制走”，必须保留原文定位；无锚点不允许保存。
2. 引用必须能定位到文档版本、页码/章节或内容块，否则导出时标记待复核。
3. 导出与分享的每一条结论都必须带原文定位；分享范围受权限规则约束。

### 3.6 时序图建议消息

1. `提交保存意图()`
2. `校验原文定位()`
3. `读取模板定义()`
4. `创建笔记()`
5. `写入批注()`
6. `绑定标签()`
7. `关联引用()`
8. `核验结论来源()`
9. `发送保存成功通知()`
10. `提交导出请求()`
11. `汇总引用与定位()`
12. `创建分享链接()`
13. `发送导出完成通知()`

### 3.7 关键异常分支

1. 原文定位失效：拒绝保存无锚点的笔记，提示用户重新选择原文片段。
2. 部分引用定位失效：导出时返回失效项并标记待复核，不静默丢弃。
3. 分享范围越权：拒绝生成分享链接。

## 4. 流程三：检索请求处理

### 4.1 流程目标

响应用户发起的检索/提问请求，在权限约束下返回可追溯的检索结果与回答结果。

### 4.2 主要参与者

1. 用户
2. 检索界面
3. 检索控制器
4. 权限规则
5. 文档集合
6. 索引
7. 证据
8. 回答结果
9. 引用
10. 通知

### 4.3 主成功路径

1. 用户在检索界面输入检索词或问题，并显式选择检索范围。
2. 检索界面向检索控制器提交检索请求。
3. 检索控制器读取用户身份、工作区与文档集合范围。
4. 系统先执行权限过滤，剔除当前用户无权访问的文档资源。
5. 检索控制器基于索引执行全文检索、语义检索或混合检索，得到候选内容块。
6. 系统根据候选内容块组装证据集合，形成本次请求的证据范围。
7. 若请求类型为普通检索，则系统直接返回排序后的结果列表与定位信息。
8. 若请求类型为问答/摘要，则系统在证据范围内生成回答结果。
9. 系统为回答结果绑定引用，确保回答中的关键结论可以回到原文证据。
10. 检索界面向用户展示结果；用户可进一步查看引用、保存笔记或继续追问。

### 4.4 关键状态变化

| 对象 | 状态变化 |
|---|---|
| 检索请求 | 已提交 -> 已过滤 -> 已检索 -> 已返回 |
| 证据 | 候选 -> 已选定 -> 已绑定 |
| 回答结果 | 生成中 -> 已生成/待复核/失败 |
| 引用 | 未绑定 -> 已绑定 -> 已核验/失效 |

### 4.5 关键业务约束

1. 权限过滤必须先于检索排序和回答生成。
2. 回答结果必须基于本次允许访问的证据范围，不能越权引用。
3. 引用必须能定位到文档版本、页码/章节或内容块。

### 4.6 时序图建议消息

1. `提交检索请求()`
2. `解析检索范围()`
3. `执行权限过滤()`
4. `检索候选内容()`
5. `组装证据集合()`
6. `生成回答结果()`
7. `绑定引用()`
8. `返回检索结果()`

### 4.7 关键异常分支

1. 无命中结果：返回空结果并提示缩小/调整范围。
2. 索引不可用：降级为原文浏览或基础检索。
3. 回答生成失败：返回证据列表或原始检索结果，不给出确定性结论。
4. 引用失效或定位失败：回答标记待复核，不作为已核验结果展示。

## 5. 三条流程的统一口径

### 5.1 统一出现的对象

- 用户
- 工作区
- 文档/文档版本
- 权限规则
- 通知
- 审计事件

### 5.2 时序图绘制时要统一的命名

| 统一名 | 不建议再改成 |
|---|---|
| 导入控制器 | 上传服务、入库模块、采集服务 |
| 笔记控制器 | 笔记服务、保存模块、导出服务 |
| 笔记 | 便签、摘录卡、note |
| 分享链接 | 外链、分享单、发布链接（本系统不产生对外公开条目） |
| 检索控制器 | 搜索服务、问答服务 |
| 回答结果 | AnswerResponse、结论对象、摘要结果 |
