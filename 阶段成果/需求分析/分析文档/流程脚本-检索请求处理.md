# 检索请求处理流程脚本 v1

对应工作包：W7（廖欣豪）。本稿以《02-关键流程文字脚本-v0.1》§4 为底稿，按 SRS、SPEC V1.0 与 UC05–UC08 补齐权限、外发和引用约束。项目名称统一为“智能笔记助手”。

## 1. 范围与参与者

- 用户通过检索界面提交检索词、问题或摘要请求，明确选择当前文档或授权文档集合；单文档请求不强行创建“文档集合”。
- 检索控制器协调权限规则、索引、证据、回答结果与引用。授权模型服务是外部参与者，不是核心业务类图中的业务对象。
- 本流程止于结果展示和引用入口；点击引用后的跳转属于 UC08 扩展行为，保存笔记属于后续 UC09。

## 2. 主成功路径

| 顺序 | 消息/动作 | 结果 |
|---|---|---|
| 1 | 用户提交请求与显式范围 | 形成检索请求（UC05/UC06/UC07） |
| 2 | 确认用户身份、工作区和所选范围，执行权限过滤 | 仅留下授权文档版本；缓存结果也必须重新过滤 |
| 3 | 检查索引对应版本及有效性，检索候选内容块 | 失效、撤权的来源不进入有效候选 |
| 4 | 组装证据，记录来源版本、页码/章节、内容块定位及置信度 | 本次证据范围固定，供结果和引用回溯 |
| 5a | 普通检索：返回按来源分组的结果列表 | 展示来源、版本、页码/章节和原文片段 |
| 5b | 问答/摘要：检查证据契约、策略与覆盖度 | 只允许合格证据进入后续生成 |
| 6b | 展示拟外发文件及版本、模型服务与用途，取得本次逐文件确认 | 拒绝或不满足策略时不得调用云端 |
| 7b | 调用授权模型服务，形成回答结果 | 状态由 `retrieving`、`evidence_checked` 进入 `generating` |
| 8b | 按本次证据 allow-list 核验每条结论的引用 | 校验 evidence_id、页码/章节、quote、原文定位及版本 |
| 9b | 返回带引用的回答或摘要 | 仅已核验引用可以作为有依据的结论展示 |

## 3. 关键分支及结果状态

| 触发条件 | 处理与状态 | 依据 |
|---|---|---|
| 权限过滤后无授权文档 | 返回空范围提示，不检索未授权内容 | UC05、ERR-301 |
| 无命中或无依据 | 返回空结果/原文片段，提示调整范围；不得伪装答案 | UC05/UC06、ERR-510 |
| 来源撤权、版本变化或索引失效 | 标记 `stale`，重新检索，不复用旧答案 | UC05/UC06、ERR-303/304 |
| 向量索引不可用 | 提示降级为全文检索 | UC05、ERR-207 |
| 证据覆盖不足 | `needs_human_review`，提示补充范围 | UC06/UC07、ERR-509 |
| 策略禁用云端、离线或用户拒绝外发 | `local_evidence_only`，只返回本地证据/原文 | SPEC §4–5、ERR-306/401/503 |
| 模型超时或失败 | `model_failed`，返回本地检索结果 | SPEC §5.2、ERR-501/502 |
| 引用不存在于 allow-list、页码越界、quote 不符或定位失败 | `citation_invalid`，不得显示为已核验答案 | SPEC §5.1–5.2、ERR-504–508 |

## 4. 命名与图面约定

图中使用《01-业务对象清单》的“权限规则、文档集合、索引、证据、回答结果、引用”等名称；“检索界面、检索控制器”是交互用边界/控制对象。Evidence Contract 作为证据准入结果出现在消息中，不新增业务类。v1 图只展示成功路径；v2 图展示必须解释的异常与降级。两张图共用本脚本。
