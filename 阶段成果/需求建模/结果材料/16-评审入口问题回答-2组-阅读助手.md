## 0. 这份文件补的是什么

启动包 §5 明确"第一轮模型评审时必须回答"这 9 个问题，但 1 组基线交付中**没有对应的回答件**——需求模型 V0.2 按"参与者 / 用例 / 规则 / 类 / 状态 / NFR / TBD"分节组织，SRS 与 SPEC 按模块组织，两者都没有按评审问题组织过内容。评审时只能临场翻材料拼答案。

本文件即该回答件。每条按三段式写：

| 段 | 作用 |
|---|---|
| **结论** | 一句话给出"能不能过"，结论只能是"是 / 部分 / 否" |
| **证据** | 模型与文档里的具体落点（编号 + 文件名），评审可现场翻 |
| **残余** | 本问题**尚未关闭**的部分，指向 TBD 编号或缺口的登记位置 |

> 原则：**凡结论说"是"的，都能在仓库里指到具体编号；指不到的一律写进"残余"，不假装已解决。** 因此本文件的"残余"段与《TBD 收口表》《RTM》§5 缺口表是同一批内容的三个视角。

## 2. 每个 AI 回答是否必须经过权限、证据契约和引用校验？

**结论：是，且是强制链，无旁路。** 三道关都挂在 AI 回答用例上，且都是 `<<include>>`（必经）而非 `<<extend>>`（可选）。

| 关 | 检查内容 | 规则 | 结构落点 | 图 |
|---|---|---|---|---|
| ① 权限 | 检索 / 缓存 / 上下文组装 / 模型调用**前**完成文档权限过滤 | BR01 | `PermissionGrant`；`Answer ..> PermissionGrant : gate` | A6（第一步即权限过滤）、A3 |
| ② 证据契约 | 授权允许外发 + 版本有效 + 契约完整 + 置信度达策略阈值 | BR02 | `Evidence`；`Answer ..> Evidence : requires contract`；`Policy.confidence_threshold` | A3（`evidence_checked`） |
| ③ 引用校验 | 引用必须来自本次 allow-list，服务端校验，不得自由生成页码 | BR03、BR04 | `Claim`、`Citation`；`support_status` 五值 | A3（`citation_checked`） |

**"必经"的证据（不是靠文字承诺，是靠关系类型）**

- 用例图 V0.3：`UC06 ..> Gate : <<include>>`、`UC06 ..> Cite : <<include>>`、`UC06 ..> UploadConfirm : <<include>>`，UC07 同样三条——**include 意味着执行宿主用例必然执行它**；只有 `Fallback` 是 extend（可选降级）。
- 状态图 A2：正常流转链 `requested → retrieving → evidence_checked → generating → citation_checked → answered`，**没有任何一步可以跳过**；任一关不过就转入分支态（`refused` / `needs_human_review` / `citation_invalid` / `local_evidence_only`），而**不存在"未校验但已是 answered"的路径**。
- 规约：UC06 主成功路径第 2/5 步、UC07 主成功路径第 2/5 步明确写出组装 Evidence Contract 与校验 claim/citation。

**残余**

- 置信度阈值是策略参数（`Policy.confidence_threshold`），**具体取值未定**——依赖 TBD-8（供应商与 SLA）。建模期冻结的是"必须有这道关且阈值可配"，不是阈值数值。
- 引用校验的**失败判据**（多大偏移算 `locator_failed`）未定，与 TBD-5（DOCX 页码策略）绑定。

## 3. 文档解析不确定、云端不可用、无依据或过期证据时，系统是否仍有明确结果？

**结论：是。** 四类异常各自有**冻结的状态名 + 用户可见的提示语 + 错误码**，没有一类是"静默继续"。

| 异常类别 | 触发条件 | 结果状态（术语表 §1.4 冻结） | 错误码 | 用户看到什么 | 图 / 规则 |
|---|---|---|---|---|---|
| 文档解析不确定 | 扫描件 OCR 低置信 | `ocr_low_confidence` → `needs_review` | `ERR-201` | "识别置信度低，已保留原页/截图" | A1、A5、BR07 |
| 文档解析不确定 | 双栏/表格/公式结构不确定 | `layout_uncertain` → `needs_review` | `ERR-202` | "结构不确定，已保留原页/截图" | A1、A5、BR07 |
| 文档解析不确定 | 解析异常 | `failed` | `ERR-203` | "解析失败，可重试或删除任务" | A1、A5 |
| 云端不可用 | 模型超时或失败 | `model_failed` | `ERR-501`、`ERR-502` | 明确失败态，可重试 | A2、A3 |
| 云端不可用 | 无网络 / 用户拒绝外发 / 策略禁止 | `local_evidence_only` | `ERR-503`、`ERR-401`、`ERR-306` | "已按你的选择不调用云端模型" | A2、A3、BR12、BR13 |
| 无依据 | 检索后无可用证据 | `refused` | `ERR-510` | "无法从当前文档确认该问题"，**不得伪装成有依据回答** | A2、BR04、BR05 |
| 无依据（证据不足但非空） | 证据覆盖不足 | `needs_human_review` | `ERR-509` | "证据不足，请补充检索范围" | A2 |
| 过期证据 | 版本变化 / 撤权 / 删除传播未完成 | `stale` | `ERR-303`、`ERR-304`、`ERR-305` | "来源已变更，引用已标记失效" | A1、A3、BR06、UC08 |
| 引用定位失败 | 引用无法回到原文 / 引用不合规 | `citation_invalid` | `ERR-504`–`ERR-508` | **禁止显示为已核验答案**（同时给 `support_status = locator_failed`） | A2、A3、BR03、BR04、UC08 |

来源：《[V0.3-SPEC错误码表](./V0.3-SPEC错误码表.md)》（44 条，覆盖 `ERR-1xx`~`ERR-6xx` + `ERR-9xx`）。

**近似失败的兜底**：BR13 / NFR-09 规定**离线时阅读与基础检索仍可用**，AI 不可用不得导致阅读器整体不可用；BR15 规定长任务必须显示进度。所以"云端挂了"不是"产品挂了"。

**残余**

- 人工复核的**可接受等待时间**未定（TBD-3）；建模期只保证"复核状态可见且不需要实测就能判断进入复核"。
- 部分状态（`citation_invalid`、`ERR-5xx`）在 SPEC V1.0 中只被"要求存在"，具体取值由 2 组补建——见 W4 的 SRS/SPEC 返修清单。

## 4. 多文档检索是否显式选择授权范围，是否能够区分来源和冲突？

**结论：范围显式——是；区分来源——是；区分冲突——部分（规则在，可视化未细化）。**

**(1) 授权范围是显式的，不是系统推定的**

- 领域模型 R-04 把 `Query "1" --> "1" DocumentSet` 改为 `Query "0..*" --> "0..1" DocumentSet`：**单文档问答不构造集合**，多文档检索才需要集合，集合由用户选择。
- A6 活动图第一步就是"选择范围"，第二步才是权限过滤（BR01）。
- `DocumentSet` 定义（术语表 §2.1）："一次检索或问答的**显式**上下文范围，**由用户选择而非系统推定**"。
- NFR-06：多文档查询默认由用户显式选择授权集合。

**(2) 来源可区分**

BR08 要求多文档回答显示**来源、版本、时间与冲突**；A6 按来源分组返回结果；`Citation` 绑定 `evidence_id` → `Evidence` → `block_id` / 版本 / 页码（术语表 §2.2）。

**(3) 冲突部分**

BR04 的 `support_status` 五值中包含 `conflicting`（冲突），即"两条证据互相矛盾"有明确表示位；但**"冲突怎么展示给用户"尚未细化**（列表式？并排式？以哪条为准？）。

**残余**

- 单次查询规模上限 **20 份**是 **NFR-06 的候选值**，未实测（TBD-2）。RTM §5 已登记为缺口。
- **冲突可视化规则未细化**——RTM §5 未单列该缺口，**本文件作为新增缺口登记**：建议在 V0.3 合并时补一条界面级说明，或明确记为"实现期细化"。
- FR-11（跨知识库/跨项目问答）**不进一期**，所以"跨库冲突"不在本期范围。

## 5. 笔记、引用、回答和原文之间是否存在稳定关联？

**结论：是。** 四类对象之间的关联在领域模型中全部显式落类，且**稳定性靠绑定版本而非绑定文档**来保证。

**关联链（领域模型 V0.3 §3）**

```
原文            ContentBlock ──→ Page ──→ DocumentVersion ──→ Document
                   ↑                （reference 的稳定锚点）
回答            Answer ──→ Claim ──→ Citation ──→ Evidence ──→ ContentBlock
                                       ↑
笔记            Note ──────────────────┘
```

| 关联 | 承载方式 | 规则 |
|---|---|---|
| Note ↔ 原文 | `Note` 关联 `document_version_id` + `block_id` | BR09 |
| Note ↔ 回答/引用 | R-05 修订后 `ExportJob "0..*" --> "0..*" Note`；`Note ⟶ Citation` 为**数据关联**（R-02 明确它不是行为扩展） | BR09、R-02 |
| Citation ↔ 原文 | `Citation.evidence_id` → `Evidence` → `ContentBlock` → `bbox` / `char_start-end` | BR03、NFR-01 |
| 稳定性 | 引用与笔记**必须绑定 `DocumentVersion` 而非 `Document`**（术语表 §2.2「Document vs DocumentVersion」） | BR06、BR09 |
| 失效可见 | 版本变化/撤权/删除 → `DocumentVersion.stale` + `Index.stale`，笔记与引用提示复核 | BR06、BR09 |
| 可回溯 | `Index` 显式保留 `version_id` 与 `stale`（R-06 新增），使 stale 传播能落到具体对象 | BR06 |

**残余**

- **定位漂移的容忍阈值与修复策略未定**（原文改版后笔记锚点偏移多少算失效）：属实现细节，与 TBD-5 相关。
- `Citation.locator` 的最终策略（DOCX 用视觉页码还是段落/标题路径）**未定**（TBD-5）。

## 7. 是否将 PDF、DOCX/Markdown、PPTX 的格式优先级转化为分阶段验收范围，XLSX/TXT 采用何种受限支持策略？

**结论：是，且已转成可判定的规则与提示语。**

| 格式 | 一期定位 | 依据 | 验收方式 |
|---|---|---|---|
| **PDF** | `Must` —— 首要输入格式，含文本型与扫描型 | SURVEY-002-Q2（18/20 选择）；V0.2 §10 FR-02；NFR-13 | 解析测试组：文本 PDF 结构化 + 扫描 PDF 走 OCR 与低置信分支 |
| **DOCX / Markdown** | 高优先级（一期） | SURVEY-002-Q2（各 11/20）；NFR-13 | 解析测试组：结构化提取 + 目录/章节树 |
| **PPTX** | 候选扩展（`Should`，**受限**） | SURVEY-002-Q2（10/20）；V0.2 §10 "PPTX 进入候选扩展范围" | 可导入登记；不承诺页面布局与演讲者注释的精确结构化 |
| **XLSX / TXT** | **受限支持** | SURVEY-002-Q2（各 4/20）；V0.2 §2.2 | 可导入登记并做基础文本提取；**明确提示"不承诺结构化问答"**，不作为一期验收项 |

**"受限支持"落到模型上的三个可判定点**

1. **不装死**：不支持的格式必须**明确提示**，不得静默失败（NFR-13）。
2. **不越界**：提示格式不支持时**不得继续遍历目录或读取其他文件**（BR11；规范化为 `ERR-101`/`ERR-102` 的前置校验，见错误码表 §2 说明）。
3. **低置信可降级**：PPTX/XLSX 等复杂版面走 BR07 —— 保留原页/截图与风险标记，`ERR-201`/`ERR-202` → `needs_review`，**不承诺精确结构化问答**。

**残余**

- PPTX / XLSX / TXT 的**一期边界线**与"复杂表格/公式/演示文稿引用的可接受准确率"未定 → **TBD-10**（`降级关闭`：建模期按"受限支持 + 明确提示"处理）。
- Markdown 方言、表格、脚注、公式、代码块的支持范围未定 → **TBD-6**（`降级关闭`）。
- n=20 的偏好排序**不等于兼容承诺**（启动包 §1 证据分层表），不得把 18/20 读成"PDF 完整兼容"。

## 8. 云端和本地模型路径是否都默认逐文件确认外发，并为拒绝外发保留离线阅读/本地证据路径？

**结论：是——但必须先纠正这题的一个前提。** 一期的**云端路径有，本地模型路径没有**。

**(1) 先把术语说清（这题的前提本身有歧义）**

| 题目里的措辞 | 一期实际含义 |
|---|---|
| "本地模型路径" | ⚠️ **一期不存在本地大模型推理路径**：FR-12「本地生成模型问答」在 V0.2 §10 中被标注为**"明确不承诺"**，RTM §1.1 记为"范围外" |
| "本地证据路径" | ✅ 存在：拒绝外发后走 `local_evidence_only`——返回**本地证据与原文**，不生成"看似有依据"的模型回答（BR12、BR05） |

> 因此第 8 题的正确答案是："**云端路径逐文件确认；本地没有模型路径，但有本地证据/原文降级路径。**" 若照题目字面回答"两条路径都逐文件确认"，会凭空承诺一个不存在的本地推理能力。
> 附带风险：SURVEY-008-Q8 问的是"**所谓本地模型场景**"下的接受度（50% 接受询问 / 35% 不接受任何上传），V0.2 §2 已标注"**需验证产品术语理解**"——用户未必分得清"本地推理"与"本地证据降级"。本项**待访谈验证**（WP-D）。

**(2) 确认机制（云端路径）**

| 要求 | 落点 |
|---|---|
| 逐文件展示范围、模型服务与用途，取得**本次**明确确认 | BR12、NFR-08；`Policy.require_per_file_consent`；`UploadConfirm` 内部用例；A4 时序图 |
| **不得默认关闭**逐文件确认 | BR12；UC11 异常路径明写"逐文件外发确认不得被默认关闭"；错误码 `ERR-404`（"该策略不允许关闭逐文件确认"，不可重试） |
| 默认不自动上传、不自动遍历 | BR11；`ModelConfig.allow_cloud` |
| 确认记录可追溯（"本次"的含义） | `AuditEvent`（只增不改）；`ERR-401` 记录 `decision=rejected` |

**(3) 拒绝外发后的降级链**

`用户拒绝` → `Fallback`（extend）→ `local_evidence_only` → 仍返回**本地检索到的原文与证据**，并提示"已按你的选择不调用云端模型"（`ERR-401`）。

**(4) 离线兜底与"路径分离"**

- BR13 / NFR-09：离线时**阅读、打开、已建索引的基础检索仍可用**，AI 入口显示明确降级状态，**不得导致阅读器整体不可用**。
- A9 界面导航图中，门控控件落点被固定在 `settings`（BR11/BR12/BR02/BR10）与 `answer-more`（BR03/BR06）两个页面，避免确认入口散落。

**残余**

- 云端模型的供应商、地区、费用、数据保留与长期 SLA 全部未定 → **TBD-8**（`建模期已关闭`：建模期只冻结"必须逐文件确认"这一机制）。
- 用户能否正确理解"本地证据降级 ≠ 本地模型"未验证 → 与 WP-D 访谈绑定；若访谈推翻，需回到 §2.4 参与者与 FR-12 的口径。

## 9. 如何在代表性样本上验证 30 秒流式反馈、1 分钟完成目标、文档打开速度和 CPU/内存上限？

**结论：建模期只能交付"验证方案 + 埋点要求 + 候选阈值"，不能交付数值承诺。** 这正是 TBD-11 仍为 `建模期未关闭` 的原因。

**(1) 指标与候选阈值**

| 指标 | 候选目标 | 出处 | 当前性质 |
|---|---|---|---|
| 首个流式反馈时延 | ≤ 30 秒 | NFR-10、SURVEY-011-Q11（30% 期望 30s 内） | **候选目标**，非验收门槛 |
| 普通问答完成时延 | ≤ 1 分钟 | NFR-10、SURVEY-011-Q11（45% 期望 1 分钟内） | **候选目标**，非验收门槛 |
| 文档打开 / 首屏时延 | 须记录耗时，阈值待定 | NFR-11、SURVEY-010-Q10（13/20 抱怨打开慢） | **必须埋点，数值未定** |
| 解析与索引耗时 | 须记录耗时，阈值待定 | NFR-11 | **必须埋点，数值未定** |
| CPU / 内存 / 并发上限 | 不得因单个大文档导致阅读器不可用，上限待测 | NFR-12、SURVEY-010-Q10 | **原则已定，数值未定** |
| 长任务反馈 | 必须有进度展示，不得无反馈等待 | BR15、NFR-10 | **可验收**（判定为有/无，不需数值） |

**(2) 代表性样本如何构成**

| 维度 | 要求 | 依据 |
|---|---|---|
| 文档长度 | 覆盖短文档（<10 页，SURVEY-001-Q1 占 50%）与长文档（>10 页，占 35%）两档 | SURVEY-001-Q1 |
| 格式 | 覆盖 PDF（文本型 + 扫描型）、DOCX、Markdown；PPTX 可选 | SURVEY-002-Q2、NFR-13 |
| 结构难度 | 覆盖纯文本、双栏、含表格、含公式、低质量扫描 | BR07 的四种低置信分支 |
| 设备 | 至少一台**低配**与一台**主流配置**，以暴露 CPU/内存上限 | NFR-12 |
| 业务场景 | 覆盖学生精读（课程资料/论文）与办公审阅（技术文档）两类 | V0.2 §3 核心场景 |

**(3) 方法**

1. **埋点**：`ParseRun`（parser_version、config_hash、warnings）、`IndexingRun`（built_at）、`AuditEvent`（occurred_at）已提供时间锚点；需在文档打开/首屏、首次流式返回、回答完成三处补埋点。
2. **压测**：按 SPEC §8 的测试组执行——"解析"组负责处理时延与资源，"引用/外发"组负责问答时延。
3. **判定**：先测出实际分布，再由"测得的 P95"反推是否接受 NFR-10 的 30s/60s；**不得先用候选值当验收线再测**。

**(4) 交付边界**

| 项 | 建模期（本轮） | 测试阶段 |
|---|---|---|
| 30s / 60s | 作为**候选目标**写进 NFR-10，标注"待压测" | 实测后决定维持、放宽或收紧 |
| 打开/解析/索引耗时 | 只要求**必须埋点**（可验收） | 实测后补阈值 |
| CPU/内存/并发上限 | 只要求"不因单文档导致不可用"（可验收） | 实测后补数值 |
| 进度反馈 | **已可验收**（有/无进度展示） | 无需实测 |

**残余**

- **TBD-11 建模期未关闭**：30s/60s 是否可达，必须在代表性设备与样本上实测。
- **TBD-9 建模期未关闭**：n=20 样本的用户类型、文档规模与使用频率是否覆盖目标群体未知，直接决定上表"代表性样本"是否真的代表性。
- **TBD-3**（解析完成/低置信/人工复核的可接受等待时间）与本问题同源，`降级关闭`。
