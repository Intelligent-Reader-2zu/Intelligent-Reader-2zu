## 2. 图件形式

本轮 11 张图以 **PlantUML 底稿（`.puml`）＋ 渲染导出图（PNG）** 的形式定稿，两部分**一一对应**：底稿是唯一结构依据，导出图是交付件，两者语义必须一致——状态名、消息顺序、泳道划分、关系方向不得改动，只允许排版差异。

| 项 | 结论 |
|---|---|
| 交付形式 | 底稿 `.puml` ＋ 导出图 `.png`（11 张，命名见 §3） |
| 试跑结论 | 平台不支持导入外部 `.puml`，逐张手工重建成本高且易产生语义漂移；本轮按「底稿＋渲染导出图」定稿 |
| 定稿日期 | 2026-10-20 |

> 说明：上述「试跑结论」为原方案的验证记录，保留备查；无论采用哪种形式，**本地 `.puml` 都是唯一结构依据**，交付件与底稿必须可对照。

## 4. 图件验收标准

| 图类 | 验收标准 |
|---|---|
| 状态图（A1 / A2） | ① 状态名与《[编号规则与术语表](./17-编号规则与术语表-2组-阅读助手.md)》§1.4 **逐字一致**；② 初始/终止态正确；③ 异常态不得增删语义，只能补细节 |
| 时序图（A3 / A4 / A5） | ① 生命线命名与领域模型类名一致；② 消息顺序与 SPEC 事件流一致；③ `alt` 降级分支**一条都不能删**；④ 不自造消息或参与者 |
| 活动图（A6 / A7 / A8） | ① A8 泳道名必须为「用户 / 系统 / 本地解析 / 云端模型」；② A8 判断条件**一字不改**；③ A6 权限过滤节点必须排在检索之前；④ A7 须体现写入前后源文件差分 |
| 修订件（用例图 / 领域模型 V0.3） | ① R-01~R-08 八条修订**全部在图上可见**；② 关系方向与多重度以《[V0.3-需求模型](./11-需求模型V0.3-2组-阅读助手.md)》为准；③ 不回退成基线画法；④ 1 组原图并存对照 |
