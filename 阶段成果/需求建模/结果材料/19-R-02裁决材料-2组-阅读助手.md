# R-02 裁决材料 · 核验引用（UC08）的宿主用例

- 提交：2 组 · 郭谦
- 日期：2026-10-20
- 用途：评审会一页纸裁决件
- 关联：[`11-需求模型V0.3-2组-阅读助手.md`](./11-需求模型V0.3-2组-阅读助手.md) §2.1 R-02、[`2组修改说明.md`](../过程材料/2组修改说明.md) §5、[`06-建模图-2组-阅读助手/底稿-PlantUML/用例图-V0.3.puml`](./06-建模图-2组-阅读助手/底稿-PlantUML/用例图-V0.3.puml)

## 1. 一句话说明

V0.2 用例图把「创建批注/笔记（UC09）」写成「核验回答引用（UC08）」的扩展（`UC09 ..> UC08 : <<extend>>`）。2 组认为这**同时有两处错**（宿主错 + 关系类型错），提出重挂方案；评审会需在下面两个方案中裁决其一。

**两个方案都不改动任何用例的内容、参与者与主成功路径，只改用例图中的关系线。**

```
V0.2 原状：  UC09 ..> UC08 : <<extend>>      （创建批注/笔记 扩展 核验回答引用）
```

## 2. 问题诊断

| # | 问题 | 说明 |
|---|---|---|
| ① | **宿主（base）选错** | `<<extend>>` 的含义是"扩展用例在特定条件下插入到基础用例中"。核验引用是用户在**看到一条带引用的回答之后**才会做的可选动作，其基础用例必然是被核验的两类回答用例——**UC06 对文档/选中文本提问**、**UC07 生成摘要/要点**，而不是 UC09。 |
| ② | **关系类型误用** | 笔记与引用之间是**数据关联**，不是行为扩展：领域模型中 `Note "0..*" --> "0..1" Answer`、`Citation`、`Evidence`。V0.2 把它画成 `<<extend>>`，属于把"数据关系"画成了"行为关系"。 |

## 3. 方案对比

### 方案 A（2 组推荐）

```
移除：  UC09 ..> UC08 : <<extend>>
新增：  UC08 ..> UC06 : <<extend>>      （核验回答引用 扩展 对文档/选中文本提问）
        UC08 ..> UC07 : <<extend>>      （核验回答引用 扩展 生成摘要/要点）
```

### 方案 B（保守）

```
仅反向：UC09 ..> UC08 : <<extend>>  →  UC08 ..> UC09 : <<extend>>
```

### 对比

| 维度 | 方案 A（推荐） | 方案 B（保守） |
|---|---|---|
| 宿主是否选对（问题 ①） | ✅ 是。宿主改为被核验的回答用例 UC06/UC07 | ❌ 否。宿主仍是 UC09（笔记），核验引用仍挂在不该挂的用例上 |
| 关系类型是否修正（问题 ②） | ✅ 是。移除 UC09↔UC08 的行为扩展，笔记与引用回归领域模型中的数据关联 | ❌ 否。仍然把数据关联画成行为扩展，只是方向反了 |
| 与领域模型是否自洽 | ✅ 自洽。`Note → Answer/Citation/Evidence` 为数据关联，图中不再出现 `Note` 的行为扩展 | ❌ 冲突。图上说"核验引用扩展记笔记"，模型里两者并无行为依赖 |
| 改动的图形元素 | 2 增 1 删（3 条线） | 1 条线反向 |
| 对用例内容/路径/参与者的影响 | 无 | 无 |
| 评审解释成本 | 需说明"本条超出原计划『修正关系方向』的表述，因为它是关系类型问题而非方向问题"（见下） | 无需额外解释 |
| 风险 | 无技术风险；仅需评审接受"按语义重挂"这一表述扩展 | **语义站不住**：若评审追问"核验引用为什么是记笔记的可选扩展"，无法给出合理回答 |

## 4. 两种方案的图示语差

```text
方案 A：
  UC06 提问 ◁── <<extend>> ── UC08 核验引用
  UC07 摘要 ◁── <<extend>> ── UC08 核验引用
  UC09 笔记        （与 UC08 之间：无行为关系，改由领域模型 Note→Citation 承载）

方案 B：
  UC09 笔记 ◁── <<extend>> ── UC08 核验引用      （仅方向反了，宿主仍是 UC09）
```

## 5. 2 组建议

**采用方案 A。** 理由：

1. 只有方案 A 同时修掉问题 ① 与 ②；方案 B 只改了箭头方向，两处错误都还在；
2. 方案 A 与领域模型（`Note` / `Answer` / `Citation` 的数据关联）**自洽**，不需要在评审时为一张图单独辩护；
3. 方案 A 不改变任何用例的行为，**对需求内容零影响**，改动只在图形表达层；
4. 现 [`06-建模图-2组-阅读助手/底稿-PlantUML/用例图-V0.3.puml`](./06-建模图-2组-阅读助手/底稿-PlantUML/用例图-V0.3.puml) 已按方案 A 落稿，若裁决采用方案 B，2 组按裁决回改即可（成本 1 条线）。

**需要评审会明确的一句话**：R-02 的处理**超出了原计划中"修正两处关系方向"的表述**——UC09 与 UC08 之间是关系**类型**误用而非方向错误，故按语义重挂而非简单反向。
