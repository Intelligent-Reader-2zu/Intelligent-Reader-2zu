# 智能笔记助手需求分析｜业务对象清单 v0.1

- 项目：智能笔记助手
- 阶段：需求分析
- 版本：v0.1
- 编制时间：2026-10-23
- 用途：作为核心业务类图、三张关键时序图与需求分析报告的统一对象底稿

## 1. 使用说明

1. 本清单只定义需求分析阶段需要稳定下来的核心业务对象，不展开数据库表设计、接口字段或部署组件。
2. 对象命名尽量沿用前一阶段需求建模中的稳定术语；若本阶段新增对象，只补业务含义，不提前写实现细节。
3. 本清单是后续类图与时序图的命名母版。若图中出现新对象，必须先回填到本清单。

## 2. 边界说明

本阶段重点覆盖三条关键流程：

1. 数据采集入库
2. 门户认领审核
3. 检索请求处理

为了让三条流程能落到同一套语义中，本阶段默认系统包含两个稳定业务域：

1. **个人阅读与智能笔记域**：文档导入、解析、索引、检索、问答、笔记、导出。
2. **知识门户治理域**：把符合条件的文档/笔记/知识条目发布到门户，并支持作者认领、审核与状态流转。

这里的“门户”指智能笔记助手中的**知识门户/内容门户**，不是外部独立平台。

## 3. 核心业务对象清单

| 编号 | 业务对象 | 对象定义 | 在哪条关键流程中出现 | 是否进入核心类图 | 备注 |
|---|---|---|---|---|---|
| BO-01 | 用户 | 使用系统进行导入、检索、认领、审核与导出的主体 | 三条流程全部 | 是 | 可细分为普通用户、作者、审核人、管理员 |
| BO-02 | 工作区 | 用户组织文档、笔记、模型策略与协作范围的业务容器 | 三条流程全部 | 是 | 是业务边界，不等于技术上的目录 |
| BO-03 | 文档空间 | 工作区下用于管理一组文档资源的逻辑空间 | 数据采集入库、检索请求处理 | 是 | 可理解为“文档库/资料区” |
| BO-04 | 文档 | 被导入、解析、索引、检索和引用的原始资料对象 | 数据采集入库、检索请求处理、门户认领审核 | 是 | 既可能是 PDF，也可能是网页快照等 |
| BO-05 | 文档版本 | 文档在某一时刻的稳定内容快照 | 数据采集入库、检索请求处理 | 是 | 支撑溯源、失效传播与引用定位 |
| BO-06 | 解析任务 | 对导入文档执行解析、切块、抽取结构信息的运行实例 | 数据采集入库 | 是 | 对应“处理并索引”过程中的任务态对象 |
| BO-07 | 内容块 | 从文档版本中切分出的可检索、可引用的最小内容单元 | 数据采集入库、检索请求处理 | 是 | 例如段落、标题、表格块 |
| BO-08 | 索引任务 | 为文档版本建立全文/语义索引的运行实例 | 数据采集入库 | 是 | 与解析任务相邻，但职责不同 |
| BO-09 | 索引 | 检索阶段实际使用的索引结果对象 | 数据采集入库、检索请求处理 | 是 | 可带 stale、build_status 等业务状态 |
| BO-10 | 权限规则 | 定义用户对文档、门户条目等资源可执行操作的授权约束 | 三条流程全部 | 是 | 先按业务规则理解，不展开权限系统设计 |
| BO-11 | 检索请求 | 用户发起的一次检索、问答或摘要查询请求 | 检索请求处理 | 是 | 是时序图中的主驱动对象 |
| BO-12 | 文档集合 | 用户显式选定的一组检索范围对象 | 检索请求处理 | 是 | 防止系统“默认跨库乱搜” |
| BO-13 | 证据 | 支撑检索结果或回答结论的原文证据对象 | 检索请求处理 | 是 | 后续与引用、回答形成追溯链 |
| BO-14 | 回答结果 | 系统对提问或摘要请求返回的结构化结果 | 检索请求处理 | 是 | 允许降级、待复核、失败等状态 |
| BO-15 | 引用 | 把回答结果与原文证据绑定起来的定位对象 | 检索请求处理 | 是 | 是“可回溯”能力的关键对象 |
| BO-16 | 笔记 | 用户基于原文、回答或引用形成的个人记录对象 | 检索请求处理、门户认领审核 | 是 | 后续可进入导出或门户展示 |
| BO-17 | 门户条目 | 在知识门户中可被展示、检索、认领的内容条目 | 门户认领审核 | 是 | 可来自文档、摘要、笔记或整理后的知识卡片 |
| BO-18 | 认领申请 | 用户对门户条目发起的归属确认申请 | 门户认领审核 | 是 | 是认领流程的主线对象 |
| BO-19 | 审核任务 | 平台为认领申请生成的审核处理单元 | 门户认领审核 | 是 | 由审核人处理并给出结论 |
| BO-20 | 审核结论 | 对认领申请给出的通过、驳回或补充材料决定 | 门户认领审核 | 是 | 可沉淀为状态变迁结果 |
| BO-21 | 通知 | 系统向用户推送的处理结果、待办或异常提示 | 三条流程全部 | 否 | 时序图常见边界对象，类图可视复杂度择机纳入 |
| BO-22 | 审计事件 | 对导入、认领、审核、外发等动作留下的追踪记录 | 数据采集入库、门户认领审核、检索请求处理 | 否 | 建议在类图中作为扩展对象视图呈现 |
| BO-23 | 模型配置 | 控制调用哪个模型、是否允许云端能力的业务配置 | 检索请求处理 | 否 | 先保留为辅助类，不一定进核心主图 |
| BO-24 | 策略 | 对引用要求、认领审核门槛、外发确认等进行统一约束的规则对象 | 三条流程全部 | 否 | 与权限规则一起构成治理侧约束 |

## 6. 当前仍需你拍板的点

### 待拍板 1：门户条目的来源范围

目前建议：门户条目可来自文档、摘要或笔记整理结果。

如果你想收紧范围，最稳的做法是只保留：

1. 文档
2. 摘要/笔记整理结果

### 待拍板 2：审核结论是否单独建对象

目前 v0.1 把“审核结论”单独列为对象，是为了让门户认领审核时序图更清楚。

如果后续类图过满，也可以把它并入“审核任务”的状态与结果属性中。

### 待拍板 3：通知/审计事件是否进核心类图

建议：先不进主图，只在时序图或说明文档里保留；除非老师特别强调“可追溯”对象显式建模。
