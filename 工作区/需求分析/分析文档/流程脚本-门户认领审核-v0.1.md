## 1. 文档定位与使用说明

1. 本文档先写"谁和谁交互、按什么顺序发生"，时序图照此绘制，不临时另起新名。
2. 命名母版仍是《01-业务对象清单》与《02-关键流程文字脚本》§5.2 的统一命名表；本脚本出现的业务对象均可在对象清单中找到对应条目。
3. 按分工约束，本脚本只补清认领、审核、状态变迁，不展开数据库设计、接口实现或部署细节。

## 2. 流程目标与范围边界

### 2.1 流程目标

当知识门户中出现某个可展示条目后，支持真实作者或责任人发起认领申请，并由审核人完成归属确认。

### 2.2 范围边界

- 本脚本假定**门户条目已存在**——内容如何发布上架门户不在本流程内。
- 管理员复核只在"审核超时"分支以消息提及，不展开其复核细节与权限实现。
- 不展开通知渠道、接口协议等实现细节。

## 4. 主成功路径（通过路径）

1. 用户在门户界面查看某个门户条目，发起"认领条目"操作。
2. 门户界面向认领控制器提交认领申请，并附带身份说明或证明材料。
3. 认领控制器校验该门户条目当前是否允许被认领（归属状态、是否锁定）。
4. 认领控制器校验用户是否具备发起认领的资格与申请条件。
5. 系统创建认领申请，记录申请人与目标门户条目之间的关联。
6. 系统为该认领申请生成审核任务，进入待审核状态。
7. 系统发送待审核通知，提醒审核人有新的认领审核任务。
8. 审核人在审核界面打开该审核任务。
9. 审核控制器读取认领申请、门户条目及其证明材料，支持审核人查看上下文信息。
10. 审核人提交"通过"结论；系统生成审核结论，更新认领申请为已通过，并回写门户条目的作者归属状态。
11. 系统向申请人发送审核通过通知，门户条目的作者归属展示同步更新。

### 5.2 分支消息

| 分支 | 触发条件 | 消息序列 | 状态落点 |
|---|---|---|---|
| B1 拒绝认领 | 条目不可认领或已锁定 | CC→门户界面：返回拒绝原因；门户界面→用户：提示暂不可认领 | 不创建申请，条目维持原状 |
| B2 审核超时 | 审核任务超时未处理 | 审核任务→CC：状态超时(待处理提醒/升级)；CC→通知：发送超时提醒或升级请求；通知→审核人：提醒复审，或升级给管理员复核 | 任务转提醒/升级，不自动出结论 |

## 6. 关键状态变化

| 对象 | 状态变化 |
|---|---|
| 门户条目 | 未确认归属/待认领 → 已认领（通过时）；驳回/待补充时**维持原状** |
| 认领申请 | 已提交 → 待审核 → 已通过 / 已驳回 / 待补充 |
| 审核任务 | 待处理 → 审核中 → 已完成 / 已超时（转提醒或升级） |
| 审核结论 | 未形成 → 已生成（通过 / 驳回 / 待补充） |
| 通知 | 未发送 → 已发送（待审核 / 补充材料 / 通过 / 驳回 / 超时提醒） |

## 7. 关键业务约束

1. **并行约束**：同一门户条目在同一时刻至多存在一个生效中的审核结论，不允许并行生效的结论相互覆盖。
2. **可追溯**：审核通过后，门户条目的归属状态必须能追溯到对应的认领申请（对应类候选集 R-18）。
3. **待补充不关单**：要求补充材料时，原申请不直接关闭，进入待补充后再复审。
4. **资格与门槛**：认领资格由权限规则约束、审核门槛由策略统一约束（BO-10 / BO-24），本脚本只使用约束结果，不展开规则实现。
5. **超时兜底**：审核超时不得自动生成结论，转为待处理提醒或升级管理员复核。

## 8. 关键异常分支与处理路径

1. **条目不可认领或已锁定**：直接拒绝并返回原因；不创建认领申请。
2. **审核任务超时**：任务转为待处理提醒或升级给管理员复核；超时不自动出结论。
3. **证明材料不足**：生成"待补充"结论，通知申请人补料，补料后复审。
4. **审核驳回**：申请落定为已驳回，条目归属维持原状，申请人可获知驳回结果。
