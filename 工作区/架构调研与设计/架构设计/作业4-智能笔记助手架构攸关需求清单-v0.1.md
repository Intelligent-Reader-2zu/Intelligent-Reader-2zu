# 作业 4 · 智能笔记助手架构攸关需求清单

> 版本：v0.1（需求基线提取稿）
> 用途：作为作业 4 架构方案比较、ADD 分析和架构视图设计的输入
> 状态：首轮提取完成；性能/容量目标及少数边界仍待组内确认
> 项目：智能笔记助手

## 1. 目的与边界

本清单从需求分析 v0.2 基线及此前技术调研/实验中提取会显著影响系统结构、数据流、部署或技术选择的需求。它不预先指定微服务、数据库、消息队列、云模型等具体技术。

需求按来源和确定程度区分：

- **已定业务约束**：已写入三条关键流程、图件或一致性检查表，架构必须满足。
- **已有调研依据的候选要求**：来自前期技术调研或实验，适合作为方案比较输入，但不自动等于已批准的产品要求。
- **待确认目标**：材料没有给出边界或量化门槛，需要组内确认后才能成为验收标准。

## 2. 架构决策摘要

当前最影响架构的约束不是“必须使用某个模型”，而是：

1. **检索与外发前必须执行授权和策略检查**，回答只能基于本次获准的文档、版本和证据。
2. **内容要可追溯**：解析、索引、证据、引用、笔记锚点均应保留到原文的位置关系；版本或定位失效时要显式标记。
3. **异步处理结果不能冒充成功**：文档只有解析和索引成功、索引可用后才算完成入库。
4. **依赖失败要有业务降级**：解析/索引、检索、引用或模型失败时，保留可用的原文、证据或待复核结果，不产生无依据的确定性结论。
5. **检索质量、响应时间、容量上限尚无经批准的数值目标**；已有小样本实验只能说明测试方向和风险，不能充当产品 SLA。

## 4. 质量场景展开

以下场景把高优先级需求写成可用于 ADD 讨论的格式。数值未由需求或教师给出时明确标为“待定”，不是默认承诺。

### AS-01 授权范围内的检索

- **刺激源**：已登录用户
- **刺激**：提交当前文档或显式选择的文档集合进行搜索/问答
- **环境**：集合中包含本人有权、无权、已撤权或版本已失效的文档
- **响应**：权限/版本过滤先于候选检索和回答；只返回获准来源；过滤后范围为空时说明需要调整范围，不泄露无权文档存在性
- **响应度量**：测试集未授权来源进入 Top-K、证据包或输出的次数为 0；撤权后缓存/旧结果的权限复核通过率为 100%
- **来源状态**：业务约束已定；生产存储、并发和缓存行为仍需实现验证

### AS-02 云端调用前的外发门控

- **刺激源**：用户发起问答/摘要
- **刺激**：当前任务拟调用外部模型
- **环境**：存在策略禁止、未确认、离线、敏感、或证据定位不完整等情况
- **响应**：仅发送获准的证据契约；其余返回本地证据/原文、待复核或拒答，不调用外部服务
- **响应度量**：所有禁止外发用例的外部调用数为 0；允许用例中请求数据与证据白名单一致
- **来源状态**：检索时序图明确要求；敏感分类规则及确认是否逐文件/逐会话需要确认

### AS-03 引用回到正确原文

- **刺激源**：用户查看问答或检索结果中的引用
- **刺激**：点击被标为有效/已核验的引用
- **环境**：原文可能更新、重新解析、被撤权，或其格式不支持页级定位
- **响应**：打开匹配的文档版本和可提供的最细定位；无法精确定位时明确显示页级/章节级/块级降级；stale 或无权限引用不冒充有效
- **响应度量**：已核验状态不得存在无效版本、越权证据或不可解释定位；不同格式分别测量定位成功率，目标阈值待样本验证后确定
- **来源状态**：引用存在及可追溯要求已定；实际引用完整率尚未达标，需实验门禁

### AS-04 文档导入的完成状态一致

- **刺激源**：用户
- **刺激**：提交一个通过导入校验的文档
- **环境**：解析或索引可能成功、失败或超时
- **响应**：系统按阶段记录任务和版本状态；解析/索引均成功且索引可用后才报告入库完成；索引失败时保留原文阅读并告知不可检索
- **响应度量**：所有“可检索/完成”版本均有对应有效索引；失败状态可区分解析失败与索引失败；对列出的异常路径逐一验证
- **来源状态**：业务约束已定；并发重复导入、重试幂等和补偿策略未在需求分析阶段规定

### AS-05 外部依赖失败时继续提供可靠能力

- **刺激源**：外部模型、网络、OCR、向量索引或引用定位组件
- **刺激**：组件不可用、超时、返回低置信结果或证据校验失败
- **环境**：用户正在阅读、检索或问答
- **响应**：按能力降级为原文、全文/BM25、已有证据、待复核或拒答；不越权、不制造确定性答案
- **响应度量**：对每种支持的失败类型执行故障注入；降级路径命中率为 100%，且权控和引用不变量仍通过
- **来源状态**：已有设计约束及局部实验支持；全链路恢复时间目标待定

### AS-06 笔记锚点和导出不丢失

- **刺激源**：用户
- **刺激**：保存或导出带引用/定位的笔记
- **环境**：原文锚点有效、过期或部分失效
- **响应**：有效锚点随笔记和导出保留；保存时失效锚点被拒绝；导出时逐项报告失效引用并标记待复核
- **响应度量**：无有效锚点的保存成功数为 0；导出时未报告而被丢弃的失效项数为 0
- **来源状态**：业务约束已定

### AS-07 交互性能和容量（待定）

- **刺激源**：用户在约定数据规模与并发量下执行导入、检索或问答
- **环境**：待指定的设备/云资源、文档格式、内容块规模、模型服务及网络条件
- **响应**：系统完成对应操作，或以可解释状态拒绝/降级
- **响应度量**：逐流程报告 P50/P95、失败率、吞吐/并发及资源占用；具体通过线需基于演示/实际目标负载由组内确认
- **来源状态**：性能是架构比较维度，但无批准的产品时限和容量门槛

| 证据 | 观察结果 | 对架构需求的作用 | 不能据此声称 |
|---|---|---|---|
| `TECH-RET-008-R01` 多文档权限过滤（合成 fixture） | 当前测试用例未授权泄露率为 0 | 权限预过滤可做成可独立测试的架构不变量；应覆盖撤权、版本和跨文档场景 | 不能外推到生产数据库、并发请求、缓存或全部真实文档 |

| `TECH-CIT` / `TECH-QA` 局部实验 | 已验证证据字段、拒答/复核及部分客户端路径；云端生成质量和端到端延迟仍有限 | 证据门控、引用白名单、人工复核状态应独立于模型适配器 | 不能据此承诺生产模型正确率、供应商 SLA 或数据合规性 |

## 6. 尚待确认的架构输入

以下项目会改变架构权衡，但当前材料不足以定案。进入架构方案比较前至少要记录当前假设：

| 问题 | 当前基线/假设 | 后续需确认 |
|---|---|---|
| 用户与协作规模 | 存在用户、工作区和授权分享等业务对象 | 单用户本地原型、多人共享部署还是两者均需覆盖；预计并发量 |
| 部署位置 | 尚未在需求分析中确定 | 用户设备、本地服务器、课程演示环境或云端；操作系统和资源约束 |
| 数据外发规则 | 检索时序图要求按策略门控并对拟外发文件/版本征求本次确认 | 哪些敏感等级可外发、默认状态、授权撤回规则、是否必须支持完全离线 |
| 文档范围 | 需求举例包括 PDF、Word、Markdown、网页快照；引用能力依格式不同 | 一期必须支持的格式与引用精度承诺，扫描件/OCR 和复杂表格是否纳入 |
| 性能与容量 | 无批准数值 | 文档数、单文档页数/大小、内容块规模、并发量、检索和问答 P95 目标 |
| 保留、删除与备份 | 要求版本和引用失效可追溯；未定义运营策略 | 原文/解析结果/索引/日志保留周期、删除传播和备份恢复目标 |
| 分享安全 | 分享链接受权限规则约束，有有效期/撤销状态 | 分享对象、接收者认证方式、有效期默认值、可否转发 |
| 审计范围 | BO-22 审计事件暂不进入核心类图 | 哪些动作需留痕，审计数据访问权限和保留期限 |

## 7. 对方案比较的约束

后续比较架构候选时，所有候选方案都必须能说明以下问题：

1. 如何让授权/版本过滤先于检索和外发？
2. 如何保存来源版本、内容块定位和引用核验状态？
3. 解析/索引任务失败时，状态和用户可用能力是什么？
4. 云端模型拒绝、离线或超时时，哪些本地能力仍可用？
5. 如何替换解析、检索和模型组件而不破坏引用和权限契约？
6. 各方案如何满足待确认的并发、时延、数据保留和部署目标？

本清单本身不决定以上问题必须通过微服务、消息队列、云端服务或本地部署实现；这些是下一阶段架构候选及权衡的内容。
