# 作业 4 · 智能笔记助手关键场景走查

> 版本：v0.1（首轮设计走查）

> 架构决策：[ADR-001](ADR-001-智能笔记助手模块化单体与受控异步处理.md)

## 1. 走查方法

本走查沿用需求阶段三条关键流程，逐步检查“触发条件 → 负责模块 → 状态/数据变化 → 用户可见结果 → 失败分支”，重点确认 ASR-01～ASR-06 是否能在推荐逻辑架构中找到承载位置。场景按逻辑模块描述，不表示各模块必须独立部署。

本稿不为未确定的性能、容量、可用性或恢复时间编造通过阈值；这些项目须在目标部署和负载明确后另行测试。

## 2. 场景一：导入文档并完成索引

### 前置条件

- 用户已进入有权限的工作区和文档空间。
- 文件通过格式、大小、权限及去重校验。
- 具体支持格式和文件容量边界仍待组内确认。

### 主路径

| 步骤 | 逻辑处理 | 状态/检查点 |
|---|---|---|
| 1 | 客户端提交文件、来源和显式导入范围；导入控制器解析身份/工作区上下文 | 请求绑定提交者和目标文档空间 |
| 2 | 权限与策略模块校验导入资格；文档生命周期模块登记文档并创建不可混淆的版本记录 | 记录来源哈希、导入时间和初始状态；版本不能被后续导入静默覆盖 |
| 3 | 任务编排器建立解析任务，调用解析器/OCR 适配器 | 任务可查询；解析结果携带块标识、定位、处理版本和警告 |
| 4 | 内容映射模块保存解析产物并更新版本状态 | 解析成功后才可创建索引任务；失败则保留原文并标记待复核 |
| 5 | 索引适配器为该版本建立全文索引及可选语义索引 | 索引状态与文档版本对应，不把部分完成状态报告成可检索 |
| 6 | 任务编排器确认索引可用，文档生命周期模块将版本标记为已索引/可检索 | 仅成功收口后报告导入完成；通知失败不改变业务完成状态 |

### 失败走查

- **解析失败**：版本保留失败/待复核状态，原文仍可读，不启动或不暴露有效索引。
- **索引失败**：原文和可用解析结果保留；该版本明确不可检索，不能被检索模块当成有效索引。
- **任务执行器中断**：任务状态必须可观察并能区分处理中、失败和完成；恢复、重试、幂等和补偿的具体实现仍需设计。

### 架构结论

- 解析和索引需要显式任务边界；首版可以同机执行，不代表必须部署消息队列或独立 worker。
- 原文/解析产物、任务/版本状态和检索索引承担不同持久化职责，但具体存储技术未定。
- 场景覆盖 ASR-04、ASR-05、ASR-09；异步任务重试与崩溃恢复仍是后续设计检查点。

## 3. 场景二：授权检索并受控调用云端问答

### 前置条件

- 用户已登录并显式选择当前文档或授权文档集合。
- 检索范围内可能混有无权、撤权、stale 或索引失效的版本。
- 云端服务为可选依赖；项目没有承诺必须联网或必须生成回答。

### 主路径

| 步骤 | 逻辑处理 | 状态/检查点 |
|---|---|---|
| 1 | 检索控制器接收请求，解析用户、工作区、请求类型和范围 | 请求范围明确，不默认跨库搜索 |
| 2 | 权限与版本过滤模块生成当前可访问版本集合 | 过滤先于候选召回、排序、融合及缓存结果复用 |
| 3 | 检索模块只读取授权且索引有效的版本，返回候选块和来源定位 | 无权文档不能进入结果，也不能通过空结果差异泄露其存在 |
| 4 | 证据模块固定本次证据集合，检查文档版本、来源定位、置信度和回答覆盖度 | 证据不足、低置信度或定位不完整时停止生成并转本地证据/待复核 |
| 5 | 若请求是普通检索，直接返回按来源分组的结果；若为问答/摘要，检查策略、网络和本次逐文件/版本确认 | 展示拟外发文件/版本、服务和用途；拒绝确认、策略禁云或离线则零外部调用 |
| 6 | 仅在所有门控通过后，模型适配器将允许外发的证据契约发送给外部服务 | 只发送 allow-list 中的证据，不发送未授权原文 |
| 7 | 回答路由器接收结构化草稿；引用校验模块核对 citation ID、quote、文档版本和原文定位 | 模型的“answered”状态不能跳过本地独立校验 |
| 8 | 检索控制器只展示已核验引用为有效结论；其他结果标记待复核、拒答或无效 | 用户可以从引用返回匹配的原文版本和可用定位 |

### 失败走查

| 触发条件 | 预期响应 | 关键不变量 |
|---|---|---|
| 权限过滤后范围为空 | 提示调整范围/权限，不执行未授权检索 | 不泄露无权文档是否存在 |
| 无命中或没有足够依据 | 返回空结果、证据或原文入口，不给确定性答案 | 召回不等于有足够证据回答 |
| 撤权、stale 或索引失效 | 丢弃旧候选并重新检索，必要时提示来源失效 | 不复用已无权或过期证据 |
| 用户拒绝本次外发、策略禁云或离线 | 返回本地证据和原文，不调用外部服务 | 外部调用次数为 0 |
| 外部模型超时、失败或结构非法 | 标记模型失败，返回本地检索结果 | 不伪造本地生成答案 |
| 引用不在 allow-list、quote 不符或定位失败 | 不显示为已核验回答，转待复核/证据展示 | 引用有效性由系统校验 |

### 架构结论

- 权限过滤、证据门控、外发确认和引用核验必须处于模型调用控制路径上，不能只放在 UI 提示或模型提示词中。
- 问答生成和模型供应商可替换；证据、权限与引用规则不应随供应商变化。
- 本地生成模型不在当前路径中；模型不可用时保留阅读、检索和证据展示。
- 场景覆盖 ASR-01、ASR-02、ASR-03、ASR-05、ASR-08、ASR-09。

## 4. 场景三：保存带锚点笔记并导出/分享

### 前置条件

- 用户对所选文档版本有访问权。
- 用户从原文选区或已核验回答结论发起保存。
- 分享范围、接收者认证方式和有效期默认值仍待确认。

### 主路径

| 步骤 | 逻辑处理 | 状态/检查点 |
|---|---|---|
| 1 | 笔记控制器接收选区、来源版本和定位信息，并解析用户上下文 | 请求携带目标文档/版本与工作区 |
| 2 | 权限模块确认当前用户仍可访问来源；锚点校验模块回源检查定位 | 无权或定位失效时拒绝保存并提示重新选择 |
| 3 | 笔记模块按模板创建笔记，关联批注、标签及引用 | 笔记保存包含可回溯锚点，不只保存一段脱离来源的文本 |
| 4 | 用户发起导出/分享后，控制器收集笔记内容并重新核验引用与锚点 | 对失效项逐项标记待复核，不静默丢弃 |
| 5 | 权限与策略模块校验请求的分享范围、有效期和访问者范围 | 越权范围不得生成链接 |
| 6 | 导出模块生成带定位信息的结果；分享模块创建受约束的分享链接 | 链接状态、范围和有效期可查询/撤销能力待设计 |

### 失败走查

- **原文锚点失效或版本不匹配**：拒绝保存；提示用户重新定位，不自动跳转到新版本替代。
- **导出时部分引用失效**：明确列出失效项和待复核状态；不能无提示丢弃。
- **分享范围越权**：拒绝创建分享链接；不以接收者拥有链接为由绕过资源权限。

### 架构结论

- 笔记、来源版本、锚点和引用关系应能一致持久化；具体事务及文件导出机制待实现设计。
- 分享权限需在创建和访问时都定义校验规则；访问认证和撤销语义尚待组内确认。
- 场景覆盖 ASR-03、ASR-06、ASR-09。

## 5. 跨场景检查与遗留设计问题

| 检查点 | 当前设计回应 | 尚未完成的设计/验证 |
|---|---|---|
| 权限何时执行 | 检索召回前；导入、笔记、导出/分享操作也检查范围 | 撤权后的缓存失效、并发请求竞态与分享访问认证 |
| 引用如何追踪 | 证据绑定文档版本、内容块及适用定位，生成后独立核验 | 对 PDF、DOCX、Markdown 等逐格式定义定位精度和有效性判断 |
| 异步任务如何收口 | 解析和索引状态分别记录；索引可用后才能标记可检索 | 任务持久化、重试、幂等、超时和崩溃恢复策略 |
| 跨存储一致性 | 业务状态、原文/解析产物、索引为不同逻辑职责 | 索引重建、删除传播、部分失败补偿和备份恢复策略 |
| 云服务边界 | 云服务为可选适配器；只接收获准证据，失败转本地结果 | 供应商条款、留存/删除、费用和持续可用性 |
| 性能与容量 | 保留独立测量入口，不设臆造阈值 | 用户数、并发、文档规模、硬件和 P50/P95 目标 |

## 6. 走查结论

候选 B 可以承载三条需求流程中的主要业务不变量：权限先过滤、导入状态如实收口、引用独立校验、外发受控、失败后保留本地证据/原文能力。需要进一步设计的重点不是增加更多部署单元，而是明确任务状态恢复、跨存储一致性、撤权后缓存处理、分享访问规则和证据定位契约。

本走查验证的是架构方案与需求流程的逻辑对应关系，不代表这些机制已经实现或通过生产级测试。部署视图中的单机环境是暂定演示剖面；在用户规模、运行位置和目标负载得到确认后，应重新走查 ADR-001 和部署图。
